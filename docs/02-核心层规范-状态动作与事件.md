# 02 · 核心层规范：状态、动作与事件

> 对应 ADR-001 / ADR-002。本文件是核心层的"宪法"，实现前通读。

## 1. 主循环形态

```
(state, action) → { state', events[] }
```

- 纯函数：同样的 (state, action) 永远产出同样的 (state', events)。
- 状态不可变：每次产出新状态，不在原对象上改。
- 随机只从 `core/rng` 的分源流取，流的消费次数也属于确定性的一部分。

## 2. 战斗状态结构（约定，实现时细化为 TS 类型）

| 字段 | 内容 |
|---|---|
| `battleId` / `seed` | 本场的种子与分流状态 |
| `turn` / `phase` | 回合数与当前相位（见 §4） |
| `player` | HP / 最大HP / 格挡 / 能量 / 污染值 / 充能 / Buff 列表 / 义体槽 |
| `enemies[]` | 每个敌人：HP / 格挡 / Buff / 当前意图 / 意图历史 |
| `piles` | 抽牌堆 / 手牌 / 弃牌堆 / 消耗堆（均为**卡牌实例**，含强化） |
| `modifiers` | 本场临时修饰列表（"本场费用-1"这类） |
| `log` 指针 | 事件序号计数器（事件带 `seq`，全局递增） |

## 3. Action 清单（v0）

| Action | 载荷 | 说明 |
|---|---|---|
| `PlayCard` | 手牌索引、目标 id（如需） | 合法性校验在 core 内做 |
| `EndTurn` | — | |
| `SelectReward` | 选项索引 | 战斗外也走同一形态 |
| `ChooseMapNode` | 节点 id | |
| `ApplyEnhancement` | 卡组索引、强化 id | 锻造祭坛 |
| `RestChoice` | 选项 id | 休息点 |
| `DebugCommand` | 指令串 | 仅调试构建生效 |

## 4. 回合状态机相位

```
battleStart → [turnStart → draw → playerAction ⇄ (敌人 intentReveal)
             → enemyAction → turnEnd] × N → battleEnd(win|lose)
```

- 每个相位切换都是事件；触发器按相位+时机挂载。
- 相位内允许动作插队（ADR-002 栈式队列）。

## 5. 领域事件清单（v0，可持续追加，**只增不改**）

| 事件 | 载荷要点 |
|---|---|
| `BattleStarted` | 敌人配置、起始手牌 |
| `TurnStarted` / `TurnEnded` | 回合数 |
| `CardsDrawn` | 抽到的卡牌实例 id 列表 |
| `DeckShuffled` | 弃牌堆洗入 |
| `CardPlayed` | 实例 id、目标、实际费用、实际卖血量 |
| `CardExhausted` / `CardRetained` | 关键词结果 |
| `DamageDealt` | 来源、目标、**各修饰层明细**、最终值、段号（多段攻击） |
| `BlockGained` / `BlockBroken` | |
| `HpLost` / `HpHealed` | 区分卖血/受伤/治疗来源 |
| `BuffApplied` / `BuffTriggered` / `BuffExpired` | 层数变化 |
| `PollutionChanged` / `ChargeChanged` / `Overloaded` | 三系机制 |
| `IntentRevealed` | 敌人下回合意图 |
| `UnitDied` | 死亡结算与队列清理结果 |
| `BattleEnded` | 胜负、奖励种子 |

> `DamageDealt` 携带修饰层明细是硬性要求——战斗日志面板和数值排查全靠它。

## 6. UI 消费规则

- UI 用**动画队列**逐事件播放；支持跳过 / 倍速。
- 同一 Action 产出的一批事件为一个"动画帧组"，组内可并行表现，组间串行。
- Pinia 状态 = 事件流重放后的投影， stores 不写任何数值逻辑。

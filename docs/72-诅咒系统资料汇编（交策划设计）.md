## §一 一分钟现状

**状态分四类半**（docs/46 §一）：异常（改数值）/ **诅咒（改规则）** / 加持 / 亡语。

| 类别 | 成员 | UI 配色 |
|---|---|---|
| 异常 | 胆怯 timid、虚弱 weak、**灼烧 burn** | 红 |
| **诅咒** | **冰缓 chill、颠倒 reverse、眩晕 stun** | **紫** |
| 加持 | 荆棘 bramble、坚韧 tenacity | 金 |

⚠️ 两个最容易混的点：
1. **灼烧不是诅咒**，是「异常」——它改的是数值（生命上限），不是规则；虽然玩家和 UI 常把它们放一起说。
2. **热修里的「超负荷 overload」也不是诅咒**（玻璃大炮专属，异常类）。

**铁律**：任何状态都**活不过一场战斗**（战斗结束全清）。这条决定了「驱散 / 净化」在上层没有位置（见 §四）。

**层数模型三型**（docs/46 §一）：

| 型 | 参数 | 衰减 | 现役成员 |
|---|---|---|---|
| 计时型 | 剩余回合 | 回合开始 −1 | 旧口径，**基本已退役** |
| 层级型 | 层数 | 不衰减，战斗结束清零 | 胆怯 / 虚弱 / 荆棘 / 坚韧 / 灼烧 / 超负荷 |
| **层数计时型** | **层数 = 剩余回合** | **承载者自己回合结束 −1** | **冰缓 / 颠倒** |

## §三 实现现状逐条（代码为准）

### 3.1 冰缓 ~chill~

| 项 | 现状 |
|---|---|
| 定义 | ~polarity: "curse"~ / ~stacking: "stack"~ / ~maxStacks: 3~ / ~decayAt: "none"~ / ~applyAs: "stacks"~ |
| 语义 | **层数 = 剩余回合**，上限 3 |
| 递减 | ~decayTimedCurses~：**承载者自己的回合结束**时 −1，归零即移除 |
| 对玩家 | 全部手牌费用 **+1**（走 ~cardCost~ 的 buff 层，~play-card.ts~；管线动态求值，不改牌面数据） |
| 对敌人 | 造成伤害 **×0.8** |
| 施加源 | 敌人：~rust_acolyte~、~deep_diver~、~drowned_choirmaster~ |
| UI | BuffRow 元数据「冰缓 / 缓 / 蓝 / 单位：回合」；glossary 有词条 |

### 3.2 颠倒 ~reverse~

| 项 | 现状 |
|---|---|
| 定义 | 同冰缓，~maxStacks: 2~ |
| 语义 | 层数 = 剩余回合，上限 2 |
| 递减 | 同冰缓 |
| 对玩家 | 回合开始把手牌费用**重掷为 0~3**，结果写进 ~BattleState.reverseCosts~（同回合内稳定，UI 预览与实付同源）；**回合内新抽到的牌同样重掷** |
| 对敌人 | 意图数值随机 **50%~150%**（~fuzzIntent~），UI 只显示「?」 |
| RNG | 独立 ~rng.stream("curse")~，不扰动 combat 流（同种子可复现，golden 兼容） |
| 施加源 | 敌人：~choir_echo~、~rust_moth~、~drowned_choirmaster~；玩家卡：**谵语 ~raving~**（2 层，自身 +2 污染） |

### 3.3 眩晕 ~stun~

| 项 | 现状 |
|---|---|
| 定义 | ~stacking: "refreshOnly"~（**不可叠加**，重复施加无效）/ ~maxStacks: 1~ |
| 对玩家 | 整回合**不可出牌**，但**仍可结束回合**（~canPlay~ 与 ~canAct~ 分开，否则会把自己锁死） |
| 对敌人 | 跳过行动 + **意图清空**；对蓄力中的敌人 = 断链 + 空转 |
| 抗性 | 精英 / Boss 数据位 ~stunResistant~：首次被眩晕后本场免疫（发 ~StunResisted~ 事件） |
| 施加源 | 玩家卡：**震爆锤 ~shockhammer~**（稀有）；敌人：~bell_warden~、~chain_flailer~、~silent_matron~、~drowned_choirmaster~ |
| validator 硬约束 | ① 敌人给眩晕**必须**同时有预告蓄力链；② 玩家侧眩晕只允许稀有卡 |

### 3.4 灼烧 ~burn~（异常，不是诅咒，但常被一起问）

| 项 | 现状 |
|---|---|
| 定义 | ~polarity: "affliction"~ / ~maxStacks: 5~ / 层级型 |
| 效果 | 回合开始每层 **−1 生命上限**，超出部分从当前 HP 扣；**战斗结束上限恢复，已损失 HP 不补** |
| 追加（甲方 2026-10-08） | 带有灼烧时**生命恢复 −50%**（在 ~healUnit~ 唯一汇点判定，先于回血结算） |
| 施加源 | 玩家卡：**锈咒 ~rust_curse~**；敌人：~corroded_swarm~、~rust_throat~、~white_slag~、~sanctum_jailer~、~forge_marshal~ 等 |

## §四 三条硬约束（你设计前必须知道，改哪条都会牵动一片）

**① 「状态活不过一场战斗」不可破，所以净化没有战斗内出口。**
docs/49 的执行记录里已经踩过一次：设计稿写「净化事件移除全部诅咒/灼烧」，但地图事件在**战斗之外**，够不到战斗内状态。最后落在**局外污染**上（净罪浅池）。要发明「驱散」就得同时在战斗内给卡牌位——这是一条**设计缺口**，不是程序没做。

**② 冰缓 / 颠倒的「层数」就是「剩余回合」，没有独立强度轴。**
所以「上 1 层诅咒、持续 3 回合」在现模型里**无法同时成立**；你要的 UI「右上角层数 + 右下角剩余回合」也会显示同一个数。
要做双轴 = 一次**状态模型变更**，牵动：~decayTimedCurses~、~cardCost~ 求值点（冰缓）、~rollReverseCosts~ / ~reverseCosts~（颠倒）、~fuzzIntent~、全部施加源数据、glossary / BuffRow、以及 golden 重录。

**③ 眩晕的行动权是「core 发状态 + UI 判定」两段式。**
core 只挂 ~stun~ 并清意图；「不可出牌但可结束回合」在 BattleView 的 ~canPlay~ 里。改眩晕的规则要同时动 UI 与 validator 那两条硬约束。

## §五 历史坑（都已修，别回头再踩）

1. **「颠倒对玩家完全不生效，状态栏也没有」**（甲方 2026-10-07 实报）
   根因：递减写在**玩家回合开始**，而敌人是在**敌方回合**挂的 → 玩家还没出手就被扣成 0。
   修法：拆出 ~decayTimedCurses~，改到**承载者自己的回合结束**递减；顺带补上「回合内新抽的牌也吃随机费用」。
   回归：~tests/unit/p28-reverse-curse.spec.ts~（4 条，含「把旧写法加回去就全红」的自证）。
2. **眩晕必须能「结束回合」**，否则玩家被永久锁死在自己的回合里。
3. **灼烧从「永久扣上限」改成「战斗内扣、结束恢复」**：原案是死亡螺旋，且玩家**没有任何反制手段**（本作无净化）。
4. **淬锈的多段叠层是有意加强**（层数模型的自然语义），不是 bug，已进真人实测观察清单。

## §六 待设计问题清单（你研究的输入）

1. **诅咒要不要「层数 × 剩余回合」双轴？** 要 → 见 §四②的牵动面；不要 → 「1 层持续 3 回合」这类表述永远落不了地。
2. **锈蚀难度开场的「随机一层诅咒、持续 3 回合」**怎么在现模型落地？（冰缓最长 3、颠倒 2、眩晕 1，且这三种的「层」都同时是回合数）
3. **诅咒的供给是否要扩？** 玩家侧目前只有 3 张卡（锈咒-灼烧 / 谵语-颠倒 / 震爆锤-眩晕），且**没有冰缓玩家卡**（docs/46 §5.2 有意不给，理由是与「虚弱」定位重叠）——要不要补？
4. **UI 角标方案**：在双轴成立前，「右上角层数 / 右下角剩余回合」会显示同一个数；要不要先按「单数字 + 单位（回合）」保持现状？
5. **要不要给「净化 / 驱散」一个正经出口？** 现设计明确不做局内净化（因为状态活不过一场战斗）——但如果诅咒变多，玩家缺反制感。
6. **冰缓对玩家是「+1 费」的定值**（不随层数变），层数只决定持续多久——要不要改成「每层 +1 费」？（这会直接改强度定位）
7. **诅咒的配置纪律还需不需要保留？** docs/46 §5.1 定过「同一场战斗至多 2 种诅咒来源、眩晕一场至多 1 次来源、灼烧战必须短轴或有前摇」——现在敌人表已经铺开（17 处诅咒施加点），这条纪律有没有被实际遵守，需要我出一份**现役敌人诅咒分布表**再谈。要的话说一声。

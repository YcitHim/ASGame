## §一 必答（会影响数值 / 手感口径）

### Q1 · `loseRelic` 会不会把职业身份件当掉？
- 现状：T1 池 8 件 = bandage / **blood_pump（血泵心脏）** / gear_coin / old_photo / **pressuregauge（压力表）** / redtear_ring / rust_dowsing / whetstone。血泵与压力表是血械 / 炉心的**职业身份件**，也在 T1。
- 于是「血之当铺 · 当货」有 1/8 概率把职业身份件当掉（换 +30% HP）。这在体验上是「卖掉自己的器官」——可能是好戏，也可能是玩家无法接受的损失。
- 选项：**(A)** 就这样，身份件也是货（**我的建议**，最有戏） **(B)** loseRelic 排除身份件（要加一个「不可失去」标记） **(C)** 当铺只当 T2。

### Q2 · 事件是不是一律不能把人打到 0？
- 现状：事件结算后的 HP **一律夹在 [1, maxHp]**。旧版允许落到 0。
- 理由：落在 0 会让下一场战斗的 `startRun` 判定「已阵亡」→ **静默重开一整局**（玩家会以为进度丢了，是排查成本极高的一类 bug）。本批顺手堵掉。
- 请确认：「事件不该杀玩家」是长期口径。

### Q3 · maxHp 变化时当前 HP 同额（+4 上限 = +4 当前），对吗？
- docs/54 E4 的括号我没能读成一个口径：「当前 HP 等比例不动」与「只动上限与当前同额」互相矛盾。
- 我按**同额**实现（+4 上限同时 +4 当前；−3 上限同时 −3 当前）。理由：+4 上限若不给当前 HP，玩家会觉得奖励被吞了。
- 若你要的是「保持比例」，说一声，改一行。

### Q4 · E6 的选项条件，程序自选了三处载体，请过目

| 事件 | 选项 | 条件 | 理由 |
|---|---|---|---|
| 废弃诊所 | a 躺上手术台 | HP ≥ 20% | 快死的人不做手术 |
| 血之当铺 | a 当货 | 至少 2 件遗物 | 「当铺不做独一件的买卖」 |
| 静默告解 | a 忏悔 | 污染 ≥ 40 | 没锈可赎就别下水 |

E6 是 §三 声明的扩展项，但 §四 / §五 的表格里**没有任何选项用到它**——不挂载体就是死代码，所以程序挑了三处最自然的，三种 kind 各覆盖一次（hpPercentAtLeast / relicCountAtLeast / pollutionAtLeast）。

### Q5 · 还有一批「写死点数」的 HP 收支没有转百分比
军规 2 说 HP 收支一律百分比、只有 ≤4 的剧情性小额才写死。§四 明确「不动」的几处仍是点数：
- 圣水涌泉 a **+10 HP**、遗骨 b **+8 HP**（§四 明写「保留为安全选项」）
- 电站 b **−4 HP**、圣泉 c **+6 HP**、净罪浅池 b **+5 HP**
要不要一起转？(A) 保持（安全档用固定数字更好读，**我的建议**） (B) 全转百分比。

### Q6 · loseRelic / removeCard / upgradeRandom 的 UI 形态
- **失去遗物**：结算页新增「失去遗物」区块（红边 + 名字划一道），与「获得遗物」在颜色上一眼分开。
- **删牌**：结算页出现卡组横排，**选完才给「继续」**（§四 E2「复用篝火选牌 UI」的落地形态）。
- **随机升级**：结算页显示「磨快了一张牌 · <卡名>」。
- **门槛**：不满足条件的选项置灰 + 红字「需要 HP ≥ 20%（当前 12%）」——置灰但不隐藏，玩家要看得见代价与收益。
- 截图：`reports/event54-cond-locked.png` / `event54-remove-picker.png` / `event54-pawn-result.png` / `event54-maxhp.png` / `event54-gamble.png`

### Q7 · 赌局赔率的机器看守（E8）只做了单向检查
validator 只检查「每个结果的百分比是否出现在选项文案里」，不检查文案里多余的百分比。
原因：文案里合法地会出现别的百分比——例：「投血（失去 6% HP；70% 回复 18% HP，30% 再失 6% HP）」，其中 6% / 18% 是代价不是赔率，全量比对会误报。
若你要更硬的门禁：建议把赔率**从文案里挪出来**，由程序按 weights 自动拼前缀（「70% / 30% · …」），文案只写结果。要做说一声。

### Q7b · E7「同幕不放回」的记账方式（程序自决，附一个真 bug 记录）
- 我记的是「**哪一层**抽到了哪个事件」而不是只记事件 id。
- 原因：只记 id 的话，结算那一刻 seenEvents 会变，同一节点重算 `rollEvent` 会掷出池里**另一个**事件——结算页的标题/正文会当场跳成别的故事。CDP 走查抓到了这个现象，已修 + 加了回归断言（`run.eventDef` 结算后仍等于刚结算的那个事件）。

## 3. 逐批次对账（docs/58 §四~§七）

### 3.1 §三 属性调整

| 职业   | 血量          | 落点                              |
| ---- | ----------- | ------------------------------- |
| 血械侍僧 | 66 → **70** | `data/classes/bloodwright.json` |
| 炉心机士 | 66 → **50** | `data/classes/engineer.json`    |
| 锈语者  | 66 → **60** | `data/classes/rustspeaker.json` |

与特性**解耦**：无特性开局同样按新血量（单测 `docs/58 §三 属性调整`）。

### 3.2 §四 血械·嗜血

- **记账**：造伤 = `DamageDealt.hpLost > 0` 且来源为玩家（未击穿格挡 → `hpLost = 0` → 不计）；自伤 = `HpLost.reason === "bloodpact"`（受击、反噬不计）。两处在 `resolve.ts` 就地累加，回合末统一结算。
- **惩罚**：未造伤且未自伤 → 力量 > 0 时力量 −1；力量 ≤ 0 时改挂 1 层虚弱（顺序即甲方裁定）。
- **奖励**：`min(⌊造伤/3⌋, ⌊自伤/3⌋) × 2` 层再生；不足一组不给（木桶取短边）。
- 3/3/2 全部落在 `data/traits/bloodthirst.json` 的 params。

### 3.3 §五 炉心·铁皮王八（四次修订后）

- **充能改道**：`attackModifiers` 与 `gainBlock` 两处同读 `traitChargeTarget(draft)`；本特性返回 `"block"` → 攻击不再吃充能、每次获得格挡 +充能层数。
- **回合末格挡生荆棘（每回合刷新）**：*自己回合结束*这一刻判定**本回合的格挡**，算出 `next = ⌊格挡 / 8⌋`，**直接覆盖**玩家身上的荆棘层数。
  - **不是累加，是刷新**：`next` 与当前层数不同才动手——先摘掉旧的 `bramble`，`next > 0` 再重新施加；`next = 0` 就只摘不补。于是「第二回合不打格挡 → 第三回合荆棘归零」。
  - **荆棘是"真状态"**：由 reducer 调 `applyBuffToTarget("bramble", n, maxStacks=brambleMaxStacks(draft))` 写进 `player.buffs` → UI 的 `BuffRow` 自动渲染「荆」图标、日志有 `BuffApplied` / `BuffExpired` 可对账。三次修订前它写在影子字段上，**这正是"没有荆棘图标"的原因**（§7 缺陷 3）。
  - 时序（步长 8）：第 1 回合打 10 点格挡 → 回合末得 1 层，第 2 回合带 1 层打；第 2 回合不打格挡 → 回合末得 0 层，第 3 回合荆棘清零。
  - `effectiveBrambleStacks()` 退化成「读 buff 层数 + 按特性上限 clamp」，不再有第二份状态。
- **上限**：`brambleMaxStacks()` 参数化，本特性 10（全局仍 5）；上限通过 `ApplyBuffInput.maxStacks` **只覆盖这一次施加**，不污染其他单位的荆棘。
- **⚠️ 与卡牌荆棘的交互（未决）**：刷新式覆盖会把**卡牌直接施加的荆棘**（荆棘血痂）一并按本回合格挡重算。是否给卡牌荆棘留一条「不被刷新吃掉」的通道，转 §8.1。
- 参数全在 `data/traits/ironhide_turtle.json`：`bramblePerBlock: 8` / `brambleMaxStacks: 10`。

### 3.4 §六 炉心·玻璃大炮（四次修订后）

- **过载关闭**：`changeCharge` 超限分支按 `chargeOverload()` 短路 → 充能不封顶、不清零、不反噬。
- **充能只是弹药**：本特性 `chargeTarget = "none"` —— 充能**不给普通攻击加伤**，只在下面的爆发那张牌上兑现（改前 `attackModifiers` 会把充能加到每张攻击上，等于免费送伤害）。
- **超负荷**：超出 10 的部分**每 5 点 1 层**，只结算新跨过的档位（`⌊(after−10)/5⌋ − ⌊(before−10)/5⌋`）。
  - 惩罚（承载者本人，敌我同构）：`tickOverload()` 在**承载者自己回合开始**扣 `2 × 层数` 点生命（非伤害、不吃格挡、可致死）；`attackModifiers` 读承载者超负荷，让**受到的伤害 +层数**（加区）。
  - 层数不衰减、战斗结束清零（层级型）。
- **一波打出去（有门槛，且先转嫁后伤害）**：每回合第一张攻击牌落到手里那一刻——
  - **身上没有超负荷 → 什么都不发生**：不消耗充能、不转嫁、不加伤，这张牌走普通结算，充能继续攒着等下回合；
  - **身上有超负荷 → 触发**：①把**自身全部超负荷整体转嫁给目标**（自身清零，AoE 则每个敌人各得一份）；②附加「当前充能」伤害并清零充能（消耗**不经 `changeCharge`**，不触发过载 / `onGainCharge`）。
  - **顺序是硬约束**：转嫁效果排在卡面效果**之前**入队（`[...spreadEffects, ...effects]`），这一击才吃得到「目标超负荷 → 受伤 +层数」。单测口径：7 基础 + 16 充能 + 1 层转嫁 = **24**（顺序反了就会是 23）。
  - 转嫁的 AOE 判定读卡面 `allEnemies`（`isAoeCard()`），走现有 `applyBuff` 效果管线，不新造平行系统。
- **蓄势（四次修订新增）**：每回合开始（含第 1 回合，开局充能恒为 0 → 必得）判定一次——当前充能 **< 10** 时额外 **+1 能量**。
  - 落点：`TraitHandler.lowChargeEnergy` → `traitLowChargeEnergy(draft)` → reducer 的 `grantLowChargeEnergy()`，在 `startBattle`（第 1 回合）与每次 `turnStart`（紧接 `energy = maxEnergy` 之后）各调一次；**只加 `energy`，不动 `maxEnergy`**。
  - 充能攒到 ≥10 即断供 → 设计意图是加速"把充能堆过阈值"的爬坡期，过载成型后不再白送。
- ⚠️ **回写事项已办**：`docs/46` §一「持续模型」表下已加回写注，登记 `overload` 为层级型的第二个合法用户。

### 3.5 §七 锈语者·超级大畸变

- **污染无上限**：`changePollution` 无上限分支；每跨过 100 的整数倍反噬 10（沿用常量），**不清零**；反噬前仍派发 `onPollutionMax`。写回局外同样不截断（`setRunPollution(run, value, pollutionCapFor(...))`）。
- **开局快照**：`computeTraitSnapshot()` 在 `createBattleState` 时算一次（≥200 触手 / ≥300 大鲨臂 / ≥400 神眼），局内跌破不失效，下一场重判。
- **胜利 −50**：`checkBattleEnd` 胜利分支在 `BattleEnded` 之前结算，玩家写回的是「已减过 50」的值。
- **保留项**：污染 ≥80 的临界惩罚与所有污染卡/遗物互动未动。

### 3.6 §十 不做的事

特性交叉组合 / 局内升级 / 排行榜联动——均未触碰。

**关于 §八.2 的一处偏离（更严而非更松）**：文档写「handler 可挂：修饰层注入、触发器时机、战斗开局快照、战斗胜利结算」——实现上没有做通用触发器注册，而是把四项能力收敛成 `TraitHandler` 上的**能力问询方法**（`chargeTarget` / `blockModifiers` / `onTurnEnd` / `onBattleWin` / `pollutionUncapped` / `firstCardFree` …）。  
理由：通用触发器会把「哪些时机特性可以介入」变成数据，而实际只有 4 档特性、时机点固定；问询式接口让**引擎侧读起来是「问引擎要能力」而不是「查特性 id」**，铁律 6 更硬、单测更好写。若将来特性数量上到两位数且时机点发散，再升级为触发器注册不迟。

## 6. sim 对照报表（三职业 × 有无特性）

口径：单幕 + normal + 每组合 **400 局**、同一批种子贯穿所有组合（特性之间的差 = 特性本身的差）。命令：`npm run sim:traits -- 400`。下表为**四次修订后重跑**的结果。

| 职业          | 特性                     | 通关率       | 相对无特性       | 平均承伤 |
| ----------- | ---------------------- | --------- | ----------- | ---- |
| bloodwright | （无特性）                  | 9.5%      | —           | 57.0 |
| bloodwright | `bloodthirst` 嗜血       | **21.0%** | **+11.5pp** | 70.0 |
| engineer    | （无特性）                  | 28.5%     | —           | 38.5 |
| engineer    | `glass_cannon` 玻璃大炮    | 4.5%      | −24.0pp     | 44.2 |
| engineer    | `ironhide_turtle` 铁皮王八 | 6.8%      | −21.7pp     | 37.0 |

| rustspeaker | `super_mutation` 超级大畸变 | 5.3%      | −1.8pp      | 30.6 |

> 四轮位移：`ironhide_turtle` 5.5% → 6.8% → 23.0% → **6.8%**。最后一次 −16.2pp 是**四次修订的直接结果**（按 docs/49 §九「单批次波动 >10pp 需解释」登记）：荆棘从「跨回合累加」改成「每回合刷新（覆盖）」后，**AI 那种"能防就防、站桩叠荆棘"的打法不再有复利**——上一轮 23.0% 的高位本来就是 AI 行为模式和"累加"口径合拍造出来的，不是特性真的强。这条位移可完全归因于口径变更，无异常。>   
> `glass_cannon` 0.5% → **4.5%**（+4.0pp）：四次修订的两处改动都指向正向（先转嫁后伤害让爆发吃满、蓄势每回合多 1 点能量），但 AI 失真条线未变（见 §6.2），**仍不可当数值结论**。

### 6.1 基线位移解释（docs/58 §九：单批次波动 >10pp 需解释）

三职业「无特性」基线相对 `docs/53` 记录的哨兵基线（血械 6.5% / 炉心 32.0% / 锈语者 10.5%）的位移：

| 职业  | 位移     | 归因                    |
| --- | ------ | --------------------- |
| 血械  | +3.0pp | 66 → 70 血             |
| 炉心  | −3.5pp | 66 → 50 血（文档明示的硬核挑战位） |
| 锈语者 | −3.5pp | 66 → 60 血             |

位移方向与幅度均与 §三 的血量调整一致，**全部 < 10pp**，无需要解释的异常波动。

### 6.2 ⚠️ `glass_cannon` 那行**不可当作数值结论**

`glass_cannon`（−24.0pp）是**AI 失真**，不是数值裁决：

1. 模拟器 AI 是「卡面启发式」（`tools/headless-sim/src/ai.ts`），**看不到特性**——它按卡面伤害/格挡打分，不会"先攒充能、等超负荷满了再一张攻击牌全兑现"，也不会"为了不被超负荷反噬而停止涨充能"；「蓄势」白送的 1 点能量它照样拿，但拿到的能量并不会被用在"攒充能"的节奏上。
2. 三次修订后爆发有了门槛（身上有超负荷才触发），AI 更吃亏了：它见到攻击牌就打，于是**每次爆发窗口都浪费在"还没有超负荷"的那张牌上**；而超负荷一旦攒出来，它又不会主动甩出去 → 每层每回合扣 2 血 + 受伤 +1 长期挂在自己身上。
3. 参照先例：`docs/program` Q2 已裁定「血械起手放血在 sim 里被 AI 误判，真人手感优先，不拿 sim 数字逼数值」。

`ironhide_turtle`（−21.7pp）**同样是 AI 塑造的，不是强弱结论**——而且这个负数被四次修订放大了：AI 的打法是「格挡卡打分 0.7× 就照打」，在**累加**口径下它能站桩把荆棘喂到上限 10（单次挨打弹 30），在**刷新**口径下站桩不再有复利，于是同一个 AI 的通关率直接腰斩。换言之这两轮之间的 16.2pp 位移，衡量的是**口径变更**，不是特性强度。

**结论**：这两行按 `docs/49 §二` 只作**回归哨兵**；特性强弱的终审必须走真人实测。真要拿 sim 说事，得先给 AI 加「特性感知」的打法（蓄力/兑牌/甩超负荷/**按格挡节奏铺荆棘**），那是另一个议题。若真人实测确认刷新口径下铁皮王八偏弱，**只改 `ironhide_turtle.json` 的 `bramblePerBlock`（8 → 6 或 5）即可**，不动任何代码。

### 6.3 顺手修掉的 AI 口径

`choosePlay` 原先用 `cardEnergyCost`（只算卡面价，不含强化与特性免能），导致触手免能时 AI 误判成"打不起"，系统性低估畸变。已改为 `previewEnergyCost(state, index)`（与 UI/结算同源）。这是**口径修正**，老 golden 不受影响（golden 走录制好的输入流，不经过 AI）。

## 7. 发现的缺陷与修复

| # | 缺陷                     | 症状                                                                                                                                                                                                                             | 修复                                                                                                                                                               |
| - | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 | 触手 / 大鲨臂的**开局快照阈值漏判**  | `traitFirstCardFree` / `traitFirstCardDouble` 只问了 handler、没查 `traitSnapshot.tentacle` / `.scythe` → 畸变在**任何污染值**下都白送「首牌免能 + 首牌双结算」                                                                                             | 两个判定各加一行快照门；单测补「快照未达阈值时都不生效」反向用例                                                                                                                                 |
| 2 | 玻璃大炮**爆发无门槛 + 充能白送加伤** | 每回合第一张攻击牌无条件吃满充能；且 `chargeTarget` 缺省 `"attack"` → 充能还会加到**每一张**普通攻击上                                                                                                                                                           | 爆发门槛 = 身上有超负荷（`firstAttackChargeBonus` 读 `ctx.buffs`）；`chargeTarget = "none"`（见 §3.4）                                                                            |
| 3 | **荆棘影子字段导致实机 NaN「秒杀」** | 铁皮王八的荆棘写在 `state.blockBramble` 上：①它不在 `player.buffs` 里 → **UI 没有荆棘图标**；②该字段一旦缺失（热更新残留的旧状态对象 / 任何未同步的构造路径），`Math.max(0, undefined)` 直接产出 **NaN** → 反弹伤害把敌人 HP 打成 NaN → `livingEnemies()` 的 `hp > 0` 判假 → **整场战斗当场判空，怪物"直接被秒杀"** | **删掉影子字段**：荆棘落地为真 buff（回合末 `applyBuffToTarget`）+ `effectiveBrambleStacks` 只做「读+封顶」；并加一道 `Number.isFinite` 护栏（数值不可靠时当 0 层，不让一场战斗凭空蒸发）；`finite-state.spec.ts` 常驻回归 |

缺陷 1 是写单测时抓到的（首批 400 局对照数字从 +46.7pp 回落到 −1.8pp 也印证了它）。  
缺陷 3 是**甲方实机截图报回来的**（"没有荆棘图标显示 + 怪物直接死 + 日志 NaN 伤害"）——三个症状同一个根因。教训：**机制状态不能有影子副本**，凡是玩家能看见、日志能记账的东西，就必须住在 `buffs` / `state` 的正规字段里；影子副本一旦和主状态不同步，产出的 NaN 会以「伤害数字」的形态直接掀桌子（`livingEnemies` 用 `hp > 0` 判活，NaN 恒假）。

## 8. 观察清单（转 `docs/49 §七.3`，不单独开疑问批次）

按 `docs/49 §二` 总方针：以下为**未决数值/设计观察项**，一律进观察清单，等 v1.1 封版前真人实测裁决。

1. **荆棘「刷新」口径下的整体强度 + 卡牌荆棘是否被吃掉**（原「累加 vs 覆盖」问题已由甲方 2026-10-07 四次修订裁决：**刷新**，见 §7.2）。
   - 强度：刷新口径下，荆棘的期望层数 ≈ `⌊每回合格挡/8⌋`，**单回合要摸到 80 点格挡才能到上限 10**，实战里大概长期停在 1~~3 层（单次反弹 3~~9）。同一批种子下 AI 通关率 23.0% → 6.8%（−16.2pp，AI 失真条线上，见 §6.2），但**方向值得真人实测验证**：铁皮王八是否从"能打的防御位"退化成"纯肉盾"。若偏弱，**改 `bramblePerBlock`（8 → 6 / 5）即可**，一行参数。
   - 卡牌荆棘：刷新是**整体覆盖**，所以卡牌直接施加的荆棘（荆棘血痂）会被回合末的判定冲掉。是否要给卡牌荆棘留一条独立通道（例如「取本回合格挡折算值与卡牌层数的较大者」），等真人实测确认这个交互是否反直觉再定。
2. **嗜血 3/3/2**：sim +11.5pp 是四个特性里唯一显著正收益，但 AI 恰好"爱卖血"（`bloodpump` 随身 + 血契卡组），可能是口径红利。真人实测时重点看：不卖血的打法下惩罚段是否过重（每回合白掉 1 力量）。
3. **超负荷的数值（每 5 点 1 层 / 每回合 2 血 / 受伤 +1）**：`overload` 仍然**没有 `maxStacks`、也不衰减**。长局里层数单调上升 → 每回合白掉的血和"受伤 +1"都会越来越大。请甲方在实测时确认三个数：①步长 5 是否太松/太紧；②每回合 2 血对 50 血炉心是否过重；③要不要给层数加衰减或上限。**另**：爆发有了「必须有超负荷」的门槛后，「什么时候把超负荷甩出去」变成一个明确的操作决策点——实测时重点看这个决策是否成立（不甩=自己持续掉血，早甩=充能还没攒够、层数还没堆够）。**再另**：四次修订后爆发变成「先转嫁后伤害」，转嫁过去的层数会**当场放大这一击**——「攒够了再甩」的收益比之前更高，实测时留意这个节奏是不是变成了唯一正解。
4. **「蓄势」的阈值 10 / 加成 1**（四次修订新增）：设计意图是加速充能爬坡期，过载成型后断供。实测时确认：①+1 能量是否够用（炉心基础只有 3 点能量）；②断供点 10 是否太早（玩家刚攒到 10 就失去加速，会不会出现"故意不攒过 10"的反直觉玩法）。两个数都在 `glass_cannon.json`，随时可调。
5. **畸变里程碑反噬 10（沿用常量）**：污染无上限后，反噬是「每满 100 一次、不清零」，长局可累计多次。10 这个数原本是"触顶一次性"的强度，改成可重复触发后是否需要下调，实测定。
6. **畸形阈值 200/300/400 与「胜利 −50」的配合**：设计意图是逼玩家不断叠污染。实测时要验证「能稳定摸到 400」的可行局占比——摸不到 400 的话神眼等于不存在。
7. **工程师 50 血**：−16 血是硬砍，三职业基线已拉开（28.5% vs 9.5% / 7.0%）。真人实测名单建议仍按 `docs/53` 的排序（血械 → 锈语者 → 炉心），但工程师现在是最脆的，实测时留意"这刀是不是砍过头"。

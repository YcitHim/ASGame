## §一 必须你裁：10 层让单幕胜率跌破 45%，而「节点配比」这条杠杆不管用

### 实测（400 局 · 同批种子）

| 口径 | engineer | rustspeaker | bloodwright |
|---|---|---|---|
| 单幕 normal（10 层树状） | **38.3%** ❌ | **31.5%** ❌ | 10.8%（AI 下限） |
| 双幕 normal（10 层树状） | **7.8%** ❌ | — | — |
| 上一版 8 层树状 | 47.3% | 25.0% | 6.5% |
| 线性图（更早） | 58.0% | 47.8% | 19.3% |

### 归因：掉的是「幕长」，不是「树状结构」

同一套生成器、同一份 act1 数据，只把中段砍回 8 层（l0~l5 + 祭坛 + Boss）：

| | engineer 单幕 |
|---|---|
| **8 层 DAG** | **50.5%** |
| **10 层 DAG（定稿）** | **39.5%** |

也就是说：**树状结构本身（50.5%）并不比线性图差，是 8→10 层多出来的两场战斗/事件吃掉了 11pp。** 这正是 §五.4 说的「幕长账」——但它不只是"时长上浮 20%"，它把单幕胜率打出了健康区间。

### §五.1 授权的补偿杠杆已试完，全部无效

| 试过的杠杆 | engineer 单幕 |
|---|---|
| 节点配比：精英 3 / 篝火 2 | 39.8% |
| 节点配比：精英 2 / 篝火 3（最保守） | 30.8% |
| 节点配比：精英 4 / 篝火 3（最贪） | 40.0% |
| **全图寻路 AI**（从 Boss 倒推 DP，按整条路线收益选点，像看全图的普通玩家） | 39.5% |

（注：早期把「精英 4 / 篝火 3」量到 48% 是巧合——那时改配比会连带把整张图重新掷一遍，比的是两批不同的地图。我把随机消耗解耦后再量，配比的影响就基本消失了。）

**结论：「地图的账地图还」这条在本轮不成立。** 单靠地图内部的节点配比，回不到 45%。

## §二 act1 的精英池只有一只怪，2~4 个精英全撞同一个

§3.2.4 要求「精英 2~4 个/幕」，而 act1 全幕只有 **`rust_warden`** 一只精英。于是 2~4 个精英节点**全是锈蚀守卫**，「同幕按层序抽、后排斥前」的精英池逻辑在 act1 形同虚设（池只有 1 件）。

- **请给 act1 补 1~2 只精英**（圣所系/锈蚀系的独立个体），或者明确指定把现有的某只小怪**升格**为精英（`riveted_heavy` 铆装重甲 / `rust_sentinel` 锈蚀哨兵 看着最像，但它们的数值是按小怪调的）。
- 不阻塞本批：现在是「同一只精英出现 2~4 次」，不是错误，只是内容量不够。

## §三 假设图里的「匣（奖励）」节点，游戏内要不要启用？

你给的可交互假设图把中段节点分成 **战斗 62% / 事件 20% / 匣 18%**。但游戏里「奖励」节点的结算挂在**战斗之后**（`RewardView`：打赢一场给三选一），地图上再放一个奖励节点会**重复发放**。

- 当前实装：**不生成奖励节点**，中段环境类型只用战斗/祭坛/事件（按 act 的 `weights`：act1 战斗 57% / 祭坛 21% / 事件 21%）。
- 要启用的话，需要你先定：地图奖励节点给什么（三选一卡？遗物？），以及它和「战斗后奖励」的关系（替代还是叠加）。**这是一条新经济，不在 §3.2「沿用现有配比」里，所以我没有自作主张。**

## §五 程序侧实现选择（不需你裁，供对账）

1. **兜底图**：§3.3 说「最多重掷 10 次后整幕重掷」，我实装为「重掷 80 次，仍不过走一张定式兜底图（三列菱形 + 固定边，数学上必过全部校验）」——保证「生成必成功」，validator 每幕 ×256 种子可以硬断言。
2. **单节点层豁免**：起点/祭坛/Boss 与相邻层**全连且不受列差限制**（按修订后的 §3.1）。中段之间仍严格列差 ≤1 且不交叉。
3. **稀有节点与随机消耗解耦**：先整体洗牌再取前 N，改动配比不会把整张图重掷——这样以后你要调配比，量出来的差异才是配比的差异。
4. **跨种子方差断言**已进 validator（每幕 ×128 种子；三分叉数 / 精英层位 / 可行路径数 / 节点总数 各有「取值数下限 + 最大占比上限」）。
5. **幕隔离**：幕 id 混进地图种子，同一 `run.seed` 下两幕生成两张不同的图。

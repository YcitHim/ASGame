# 01 · 架构决策记录（ADR）

地基级决策。**修改任何一条，必须先改写对应条目并注明日期与理由。**

---

## ADR-001 核心层事件溯源

- **决策**：核心层主循环形态为 `(state, action) → { state', events[] }` 纯函数。
  UI、战斗日志、回放记录全部是事件流的**消费者**，核心层不直接通知任何人。
- **理由**：动画时序天然对齐；回放 = 种子 + 输入流；golden replay 回归测试；调试面板免费获得。
- **代价/纪律**：核心层不允许"顺手改状态"，任何变更都必须落成事件；UI 不得绕过事件流直接读内部中间态。

## ADR-002 效果管线 = 栈式动作队列

- 连锁触发产生的新动作**压栈**（后进先出），保证"杀死后抽牌再触发"这类链条有序。
- **死亡清理规则**：单位死亡时，清除队列中所有以它为来源或目标的挂起动作。
- 多段攻击（如低血沸腾三连击）拆为多个独立伤害动作，每段独立触发 onHit。

## ADR-003 修饰符管线（Modifier Pipeline）

- 一切对外数值（伤害 / 费用 / 抽牌数 / 卖血量 / 格挡）= `基础值 → 升级 → 强化 → Buff → 本场临时修饰`，逐层有序求值。
- priority 表、乘加顺序、clamp 规则见 docs/03，属于冻结规范。

## ADR-004 注册制

- 五类注册表：`condition`（条件）、`target`（目标选择器）、`keyword`（关键词）、`cardHandler`（卡牌复杂逻辑）、`enhancementHandler`（强化逻辑）。
- JSON 中只允许出现**已注册的 id + 参数对象**；未注册 id 在构建期校验直接报错。

## ADR-005 卡牌逻辑混合模式

- **简单效果**走 JSON 声明式（damage / draw / block / heal…），目标覆盖 80% 的卡。
- **复杂机制**走注册 handler（TS 函数，可单测、有类型），JSON 只写 `{ "handler": "xxx", "params": {...} }`。
- 只有真正的新机制才允许新增 handler；新卡优先复用已有 handler。

## ADR-006 RNG 分流

- 随机流：`combat` / `reward` / `map` / `ai` / `fx`，各自从主种子独立派生。
- 任一流内部逻辑变更，不得影响其他流的随机序列（否则旧回放全部失效）。

## ADR-007 移动端方向（2026-10-05 拍板：方案 A）

- **决策：0.1 锁定横屏 + 旋转提示。** 竖屏双布局顺延到 0.5 之后评估。
- 理由：杀戮尖塔式布局天然横向；双布局等于战斗 UI 两套排布与两套测试，成本与 0.1 竖井目标不符。
- 落地约束：
  - 基准画布 1280×720 等比缩放适配（docs/08 §4），手机横屏即同一套锚点布局
  - 竖屏时显示「请横置设备」旋转提示遮罩，不渲染战斗界面
  - 手牌区在窄屏横屏下允许底部横向滑动；意图图标常驻敌人头顶（docs/06 §2）
- **代价**：横屏手机上浏览器的地址栏会挤压可视高度，100dvh + 缩放留白需在 W6 真机验证。

## ADR-008 存档版本化

- 所有存档带 `version` 字段；读取走 migration 链逐级升级；**从第一天实现**。
- 存档 schema 任何变更 = version +1 + 新增一个 migration 函数。

## §一 现状诊断

当前分组两处真问题：

1. **血械池成了公共卡堆放处**：43 张（炉心/锈语者各 29）。打击、防御、直刺、快切、横扫、铁皮……全系在血械名下（`strike.json` 的 `"class": "bloodwright"`），职业池隔离（docs/16 §5.2）意味着**炉心和锈语者在奖励里永远见不到这些通用卡**。
2. **身份卡错放他池**：充能卡（chargeup/sparkjab/redline/discharge/overloadstrike/kineticcell——炉心身份）和污染卡（blightoffering/bloodrust/corrode/rustspray/plaguesurge/purge/corrodededge——锈语者身份）全在血械池里。血械奖励能抓到充能卡，但血械没有任何充能来源——**抓了就是死牌**。电站事件为此专门留了个「职业不匹配就保留原池」的特例补丁，根子就在分组错了。

`cards/_shared/` 是空目录占位，从未启用。

## §二 判定规则（唯一标准：机制身份，不是风味）

**归属判定按「身份指纹」：卡面（含升级面、能力面）命中任一身份指纹 → 对应职业池；谁都不命中 → 中立池。风味（名字/文案带蒸汽或锈味）不构成归属理由。**

| 职业 | 身份指纹 |
|---|---|
| 血械侍僧 | `bloodpact` 关键词 / `bloodCost` / `cond:hpBelow`（低血收益）/ `cond:tookDamageThisTurn`（受击反击）/ `heal`（吸血与回血，血池循环）/ `buff:mending` / `consumeBoons` |
| 炉心机士 | `gainCharge` / `spendCharge` / `chargeCost` / `chargeFromEnergy` / `bankCharge` / `cond:chargeAtLeast` / `buff:tenacity`（维续装甲）/ `power:onGainCharge` |
| 锈语者 | `gainPollution`（**仅正值**）/ `transferPollution` / `consumeCorroding` / `cond:pollutionAtLeast` / `buff:corroding` / `buff:burn` / `buff:reverse` / `buff:regeneration` / `power:onPollutionMax` / `cond:targetHasBuff` |
| 通用（不构成身份） | damage/block/draw 三件套、`buff:weak` / `buff:timid` / `buff:strength` / `buff:bramble` / `buff:stun`、`gainModifier:attackDamage` / `gainModifier:backlashTaken`、`power:onBlock/onHit`（不挂身份资源时）、retain/exhaust/innate 等通用关键词 |

> **甲方 2026-10-08 修订（本节现行口径，四改）**——因应「净化 / 腐蚀 / 铁胃 / 震爆锤改中立、炉渣装甲改炉心」的裁定：
> ① 炉心**去掉** `buff:stun`：眩晕是通用控制（震爆锤是唯一来源），不构成充能身份；
> ② 锈语者**去掉** `modifier:backlashTaken`：它同时修饰过载反噬与污染失控，是通用减伤；
> ③ `gainPollution` 收紧为**正值**才算：净化类（负值）是把全局污染往下按，任何职业都该能用；
> ④ 炉心**补入** `bankCharge`：上发条改版后的新效果，同样是充能机制。
> 原「铁胃的边界裁定」（本文下方）已被 ② 推翻。详见 `docs/59 §四`。

**铁胃的边界裁定**：`backlashTaken` 同时修饰过载反噬与污染失控（resolve.ts:297 两reason共用）——它碰的是身份资源，**不属于中立**；留锈语者（污染失控减噬是主用途）。

## §四 奖励与事件集成

1. **战斗奖励三选一**：每个槽位独立掷——**70% 职业池 / 30% 中立池**，池内稀有度权重照旧。中立池全职业共享、终身可见。
2. **事件 `gainCard`（无显式池）**：同上 70/30。
3. **事件显式池语义修正**（顺手拔掉 docs/16 的特例补丁）：显式池按「职业可用性」过滤——本职业与中立可用卡保留；**若过滤后为空则退化为中立池抽取**（不再保留原池发死牌）。电站事件池（4 张充能卡）对非炉心职业自此发中立卡。
4. **起始卡组 / 教学 / 调试**：按 id 引用，不受分组影响（strike/defend 现在是中立 starter，三职业起始卡组照常引用）。
5. **图鉴**：新增「中立」分组页签，置三职业之后。
6. **解锁**：各卡 `unlockCondition` 原样保留，中立卡按原条件解锁。

## §五 validator 双向守卫（机器看守分组铁律）

- **中立禁纹**：中立池卡命中任一身份指纹（§二表）→ 报错。以后谁往中立池塞身份卡，validator 直接拦。
- **职业验纹**：职业池卡未命中**本职业**身份指纹 → 报错。
- **两处豁免（甲方 2026-10-08 补）**：
  - **衍生物** `token: true`（铁拳）：不进任何池，分组规则不适用 → 跳过指纹校验；
  - **人工登记** `CARD_CLASS_PINS`：指纹扫不出来的个案（炉渣装甲 / 超械铁拳，甲方裁定归炉心）
    显式登记跳过校验；登记与数据 class 不符时**报错自曝**（登记过期不会隐身）。
    先例：`ui/relic-fit.ts` 的 `MANUAL_CLASS_ONLY`（`docs/43 §2.4`）。
- 指纹表作为 validator 的显式注册表维护，新增身份机制（如未来的诅咒牌）先入表再入池。

## §七 不做的事

1. 不动任何卡的数值/稀有度/升级面——本次只改归属；
2. 不删血械的「死牌隐患」旧账以外的卡——分组后血械奖励里自然不再出现充能卡，问题自愈；
3. 不为中立池设计新卡（池子先立起来，新中立卡随以后的内容批走 §二 规则自然归入）；
4. 不动 70/30 以外的配比参数——比例先跑 sim 观察，实测手感再调。

### 走查抓到的两处真问题（顺手修）
1. **Boss / 多敌同屏时敌人状态栏被玩家面板盖住**（甲方报「boss 状态栏看不见信息」）。
   - 根因：`.enemy-zone` 与 `.field-band` **同 z-index(10)**、后者在 DOM 里靠后 → 重叠区后者赢；敌人内容实际高达 y≈386（舞台坐标），而战场带从 340 开始，最左那只敌人的状态芯片整排压在玩家面板底下。
   - 修法两层：`.enemy-zone` z-index 10 → **12**（敌人状态恒在战场带之上）；敌人状态包一层 `.enemy-buffs`，`max-height: 116px`（**恰好三排**）超出内部滚动。三排是实测上限：三排到 y=500，手牌区从 508 起（z 20），再多一排就会被卡面盖住——原来无上限时三排刚好可见，所以卡在三排而不是两排。
   - 实测：12 条状态三排 **0 条被挡**、与手牌间距 43px；2 敌同屏（各 10 条）**0 条被挡**。
2. **图鉴「中立」页签显示 0 张**：过滤口径是「不在职业表里」，计数却按 class 名分桶，两者不一致。已统一为同一判据（修后中立 20）。

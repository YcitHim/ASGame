# 54 · 事件系统扩充与改版设计

> 整理：策划 · 2026-10-07
> 缘起：玩家反馈「增加更多随机事件，改善原本的事件内容；命运齿轮只会固定扣 24 血，不合理；事件需要有利有弊」。
> 结构：§一 核查结论 / §二 事件设计规范（三条军规）/ §三 引擎扩展清单 / §四 既有事件逐件改版 / §五 新事件批（+8）/ §六 批次与门禁

---

## §一 核查结论

### 1.1 命运齿轮的「24 血」对不上账——但批评成立

当前数据（`gear_gamble.json`）：押注 = 先 −8 HP，再 50/50（赢 → 随机遗物 / 输 → 再 −8）。**最坏 −16，不存在固定 −24**。玩家可能遇到的是旧版本、或两次遭遇记混。但三条设计批评全部成立：

1. **数值是平的**：固定 −8 对开局是割肉、对后期是挠痒——固定数值事件天然不公平，应该跟最大生命挂钩；
2. **赌局是闷的**：权重 1:1 玩家看不见，「赌」变成了「猜」——赌局不示赔率就是耍流氓；
3. **选项是瘸的**：只有「押 / 离开」两档，没有风险梯度。

### 1.2 全事件审计（11 个）

| 问题 | 波及事件 |
|---|---|
| **纯收益零代价**（违反「有利有弊」） | 朝圣者遗骸（遗物或 +8 HP 白拿）、圣泉（三个选项全收益）、电站 a（充能卡白拿） |
| **逃避反被罚**（负收益选项凑数） | 溺唱诗班 b（−4 HP 换空气，比离开还亏） |
| **固定数值不缩放** | 全部 HP 收支都是写死点数 |
| **效果种类贫瘠** | 引擎只支持 5 种效果（hp/pollution/gainRelic/gainCard/gainEnhancement）——没有删牌、没有升级、没有 maxHp、没有失去遗物 |
| **结构性空缺** | **全游戏没有删牌渠道**——构筑洁癖玩家零出口，这是比单个事件更大的窟窿 |

## §二 事件设计规范（三条军规，后续所有事件适用）

1. **利弊同捆**：每个事件至少一个选项是「甜枣 + 巴掌」同捆；允许存在一个「安全但平庸」的选项（离开/小额纯收益），但**不允许**全事件所有选项都纯收益，也不允许存在「纯惩罚凑数」选项。
2. **代价随人缩放**：HP 收支一律用**最大生命百分比**（取整、最低 1）；只有剧情性小额（≤4）才允许写死点数。
3. **赌局明示赔率**：带 `outcomes` 的选项，选项文案必须写明概率与输赢结果（「60% 得 …，40% …」）——赌可以，闷赌不行。

## §三 引擎扩展清单（枚举字段式，不动结算管线；程序评估后排期）

| # | 扩展 | 说明 |
|---|---|---|
| E1 | 新效果 `hpPercent` | 按最大生命百分比 ±HP，向下取整、最低 1；军规 2 的载体 |
| E2 | 新效果 `removeCard` | 玩家从卡组**选一张**删除（复用篝火升级的选牌 UI，仅展示不可升级限制改为不可删限制）；降级方案 `removeStarter`（随机删一张打击/防御） |
| E3 | 新效果 `upgradeRandom` | 随机升级一张未升级牌（无可升级则落空，文案兜底） |
| E4 | 新效果 `maxHp` | ±最大生命（当前 HP 等比例不动，只动上限与当前同额） |
| E5 | 新效果 `loseRelic` | 失去指定 tier 的随机一件遗物（默认 T1）；血之当铺用 |
| E6 | 选项级 `condition` | `hpPercentAtLeast` / `pollutionAtLeast` / `relicCountAtLeast`；不满足置灰 + 小字注明缺什么（沿用 docs/43 置灰标注组件） |
| E7 | **同幕事件不放回抽取** | 事件节点从幕池抽后不放回，池尽重置——一局两幕不再连撞同一个事件 |
| E8 | validator 规则 | 赌局类（含 outcomes）选项 label 必须含百分比数字，且与 weights 推算概率一致——军规 3 的机器看守 |

golden replay 为战斗盘回放，以上全部为局外（run 层）变更，**golden 应逐位一致**；sim 观察基线随事件经济变化重记一次。

## §六 批次与门禁

| 批次 | 内容 | 门禁 |
|---|---|---|
| **V1 引擎扩展** | §三 E1~E8 全部 | 每种新效果 ≥2 例单测（含边界：池空/无可删/无可升级/条件不满足置灰）；validator 新增 E8 规则；golden 逐位一致 |
| **V2 事件改版** | §四 11 件逐件改版 | validator + i18n 校对；sim 观察基线重记 |
| **V3 新事件** | §五 8 个新事件 + i18n 文案（文案风格沿用现有「锈味」笔法，程序录入后我校一遍） | 同上；act 池配比进 validator（act1 事件 ≥8、act2 ≥6） |

**依赖关系**：V2/V3 依赖 V1（hpPercent/删牌/条件都要新引擎）。V1 可插在任意表现层批次之间——它是 run 层变更，与战斗结算零交集，不与 M3 分裂冲突。
**明确不做**：① 不做诅咒牌进卡组（牌组级诅咒是另一个系统，本文不碰）；② 不做事件连锁/后续事件（单发自足）；③ 不动事件节点在地图上的配比（docs/48 已冻结）。

## 程序执行记录（2026-10-07）

三个批次一次做完（V1 → V2 → V3；V1 是 V2/V3 的前置），门禁全过。

### V1 引擎扩展（E1~E8）

| # | 落地形态 |
|---|---|
| E1 `hpPercent` | 按最大生命百分比取整（**向下取整、最低 1**），引擎里直接折算成绝对 `hpDelta`——UI 显示的与结算是同一个数 |
| E2 `removeCard` | 结算返回 `removeCard` 标志，结果页弹出卡组横排**由玩家自选**，选完才给「继续」。降级方案 `removeStarter` 未实现（主方案能用就不留死代码） |
| E3 `upgradeRandom` | 可升级候选下标由调用方传入（core 不反向依赖卡组），引擎用事件 RNG 抽一张返回 `upgradeIndex`；无可升级则 `-1` 落空、文案兜底 |
| E4 `maxHp` | 引擎只返回 `maxHpDelta`，当前 HP 的「同额」由 `applyEventHp` 单点写回（与 `hpDelta` 一起夹进 `[1, maxHp]`） |
| E5 `loseRelic` | 按 `tier`（默认 1）过滤持有列表后用事件 RNG 抽，返回 `loseRelicIds` |
| E6 选项条件 | `condition: { kind, value }` 三种；`checkEventCondition` / `eventConditionCurrent` 同源（UI 用它置灰 + 写「当前 X」），core 在结算入口再拦一道 |
| E7 同幕不放回 | `RunState.seenEvents` 记「**哪一层**抽到哪个事件」；`rollEvent` 先查本层记录，命中即原样返回，否则从「本幕没用过」的池里抽，池尽重置回全池；转幕清空 |
| E8 validator | 含 `outcomes` 的选项，label 必须写出每个结果的百分比（**单向**检查，理由见第九批 Q7）；另加事件池配比门禁（act1 ≥8 / act2 ≥6）与新效果取值校验（hpPercent / maxHp 不得为 0、loseRelic 的 tier 限 1~3） |

- 存档：`SCHEMA_VERSION` 13 → 14，迁移只给带 `run` 的进度档补 `seenEvents: []`。
- **三处口径自决**（已开第九批 Q1/Q2/Q3）：事件 HP 一律夹在 ≥1；maxHp 变化时当前 HP 同额；loseRelic 不排除职业身份件。

### V2 既有 11 件改版 / V3 新事件 +8

- 11 件按 §四 逐条落地：命运齿轮三档风险梯度（小押 −8% / 大押 −15%，赔率写进文案）、遗骨搜刮 +8 污染、圣泉 +12 → +10、电站白拿 +5 污染、溺唱诗班「捂耳离开」改无代价、换血人 / 垂死 / 圣泉 / 沉没祭品 / 净罪浅池一律转百分比、鸣钟不动。

### 走查与门禁

- **CDP 真机走查**（dev server，逐事件锁池）：置灰门槛（当货 ·「需要至少 2 件遗物（当前 1）」/ 忏悔 ·「需要污染 ≥ 40（当前 0）」）、当货掉遗物 +30% HP、活扳手上限 +4 且顶栏当场 `HP 65 / 70`、废弃诊所删牌选择器（选完前没有「继续」）、命运齿轮三档赔率文案、静默告解上限 −3 且污染 −40。
- **走查抓到一个真 bug**：E7 原先只记事件 id → 结算那一刻 `seenEvents` 变化，同一节点重算 `rollEvent` 会掷出池里**另一个**事件，结算页的标题 / 正文当场跳成别的故事。改成「按层记账 + 本层已抽过则原样返回」，并加了回归断言。
- 校验：lint / typecheck / validator（卡 101 · 强化 12 · 敌 25 · 遗物 25 · **事件 19** · 职业 3 · 关卡 2 · i18n **824**）全绿；单测 **521 例 / 73 文件**（`event.spec` 重写为 16 例，覆盖 E1~E7 + 军规自查）；**golden 7 盘逐位不变**（事件是局外变更，与战斗结算零交集）。
- sim 观察基线重记（400 局 / 单幕）：炉心 42.5% / 锈语者 12.0% / 血械 7.8%；双幕炉心 11.5%（act2 偏难是 docs/53 §二 既有观察项）。**sim 侧同步补齐了对新效果的认识**（原先不传 maxHp、不应用 maxHp / loseRelic / removeCard / upgradeIndex，新型事件在它眼里几乎全是 0 分，AI 会退化成「总是选第一个」）——不补这一刀，基线数字不可比。

# 51 · 战斗反馈强化与资源转换经济（三条玩家反馈）

> 整理：策划 · 2026-10-07
> 缘起：三条玩家反馈——① 格挡/挨打数字太小气「不注意看都瞅不着」；② 能量获取途径太少、构筑不出刷牌引擎，想要资源转换（耗血得能量/得牌等）；③ 拖动出牌后悔无法取消。
> 三条全部成立。现状已核码：飘字 34px（big 48px）贴单位头顶；`gainEnergy` 全卡池仅 **6 处**；`pointerup` 落在任何位置都直接 `playCard`（无目标卡拖到哪都打出去）——③ 是交互缺陷实锤。
> 结构：§一 重读数（大字飘字体系）/ §二 资源转换经济（新卡批）/ §三 拖动取消规格 / §四 批次与门禁 / §五 不做的事
> **反馈系列索引**：docs/41（首批 11 条）→ 本文（次批 3 条）→ `docs/52`（第三批 3 条：附魔可视/状态栏/首回合遗物；其 G2 批与本文 F1 同为表现层批，合并施工验收）。

## §一 「重读数」：事件级大字飘字

**问题定性**：现有飘字是「信息层」（34px 贴头顶，给谁看都够），缺的是「情绪层」——重击、濒死、完全格挡这些**战斗的高光时刻**没有高光待遇。玩家的诉求不是把数字都放大（那是刷屏），是**关键时刻要有冲击力**。

**设计：两级飘字体系**。常规飘字一字不动（信息层，v1.0.2 刚磨好），新增「重读数」一级：

| 项 | 规格 |
|---|---|
| 位置 | **舞台中轴偏上**（敌人区与手牌区之间的视觉焦点带），不贴单位头顶——中央出现 = 余光必达 |
| 字号 | **64~96px**（按事件分级），弹性缩放入场 + 1.2s 停留（常规飘字 0.9s） |
| 触发（四档，取严不取宽） | ① **重创**：玩家单次受伤 ≥ 最大 HP 15% → 血红大字「−N」+ 短震屏；② **完全格挡**：单发 ≥10 的伤害被全挡 → 冰蓝大字「完全格挡！」（现在的「格挡！」24px 小字升级为事件）；③ **重击**：玩家单次打出 ≥20 伤害 → 锈金大字「−N」（爆发的爽感回授）；④ **致命**：击杀精英/Boss 的一击 → 描金「击溃」 |
| 防刷屏 | 同帧只出一个重读数（取数值最大者，其余回落为常规飘字）；连续重读数间隔 ≥0.4s |
| 阈值口径 | **一律用相对阈值**（最大 HP 比例 / 敌方最大 HP 比例），不用绝对值——act1 的 20 和 act2 的 20 不是一回事，绝对阈值后期必然失灵。上表数字为 act1 基准参考值，程序按相对口径换算 |
| 工程 | 走 anim-queue 事件订阅（同 v1.0.2 先例），**不碰结算时序**；`battleAnim` 三档联动——simple 档保留文字去震屏，off 档关闭 |

## §二 资源转换经济：让每个职业都有「引擎件」

**问题定性**：`gainEnergy` 全池 6 处、`draw` 27 处且多为职业机制附带——能量是纯粹的「每回合 3 点死工资」，构筑维度里**没有「引擎」这个槽位**。甲方举的例（耗血得能量/得牌）正中血械职业身份，方向批准。

**总设计：每职业 2 张转换卡，风格各异但共用一套防失控护栏。**

### 2.1 新卡批（6 张）

| 职业 | 卡 | 费 | 效果（基础 / 升级） | 转换逻辑 |
|---|---|---|---|---|
| 血械 | **血涌** | 1 | 血契 2 → 能量 +1、抽 1 / 血契 2 → 能量 +2、抽 1 | 血 → 能量（甲方点名的原型） |
| 血械 | **祭血狂热** | 2 | 血契 3 → 抽 2 / 血契 2 → 抽 2 | 血 → 牌 |
| 炉心 | **回压阀** | 1 | 消耗 2 充能 → 能量 +1、抽 1 / 消耗 2 充能 → 能量 +2、抽 1 | 充能 → 能量 |
| 炉心 | **齿轮过驳** | 0 | 消耗 1 充能 → 抽 1 / 消耗 1 充能 → 抽 2 | 充能 → 牌 |
| 锈语者 | **锈蚀代谢** | 1 | 污染 +6 → 抽 2 / 污染 +5 → 抽 2 | 污染 → 牌 |
| 锈语者 | **污能转化** | 0 | 污染 +5 → 能量 +1 / 污染 +4 → 能量 +1 | 污染 → 能量（rustcommunion 的下位日常件） |

稀有度：血涌/齿轮过驳/污能转化 common，其余 uncommon。升级口径沿用 docs/50 惯例：**获取量不随升级膨胀**（能量净增封顶 +1 的破例仅限血涌/回压阀的「减费提效」），升级主要减代价或加副收益。

### 2.2 防无限循环护栏（铁律，违一条打回）

1. **转换必耗牌位**：转换卡打出去自身 −1 手牌，**净抽牌 ≤ +1/张**——「抽 2」是给下回合存的，不是当回合白赚；
2. **能量净增 ≤ +1/张**（0 费换 1 能 / 1 费换 2 能封顶）——刷牌可以转得快，不许越转越多；
3. **不设永动联动**：本批不出「转换触发转换」的遗物/强化（docs/46 不做的事③「不新增遗物」继续有效）；
4. **代价即刹车**：血契扣血、充能消耗、污染积累——每个引擎都自带燃料表，烧完就停。这是「刷牌」在本作的合法形态：**有预算的循环，不是无限**；
5. 若真人实测出现无限组合：先改稀有度/代价，不改机制——预案冻结于此。

### 2.3 与既有卡的关系

bloodrite（0 费血 1 换 1 能）、rustcommunion（污染换 2 能）不动——新批是**补槽位**不是替代：6 张新卡 + 既有 2 张，每职业 3~4 件引擎候选，「刷牌流」第一次成为可构筑的原型。

## §三 拖动取消规格

**问题定性**：`pointerup` 不看落点直接 `playCard`——无目标卡拖到哪都打出去，目标卡拖空了才哑火。这不是「缺少取消按钮」，是**落点判定根本没做**。

| 项 | 规格 |
|---|---|
| 合法落点 | 目标卡：松手时 `hoverEnemy` 命中才结算；无目标卡：松手在**出牌区**（舞台上半部，敌人区至中轴一带）才结算 |
| 取消路径（三条，全都要） | ① **拖回手牌区松手** = 取消，牌弹回原位（最直觉，主力路径）；② 拖动中按 **ESC 或右键** = 立即取消；③ 松手在**任何非合法区**（空白、UI 面板、日志上）= 取消弹回——「没拖到地方就是不想出」，绝不替玩家做决定 |
| 拖拽中反馈 | 指针悬在手牌区时**手牌区描边高亮**（提示「松手取消」）；幽灵卡在不可结算位置**降为 50% 透明**，进入合法落点恢复实色——取消权是看得见的 |
| 瞄准模式统一 | 轻点选中进入瞄准态的卡，同样 ESC/右键/点空白处取消（与拖拽口径一致，顺手统一） |
| 弹回动画 | 0.2s 回弹到手牌原位，无消耗、无日志——取消不是事件，不该留痕 |

## §五 不做的事

1. **常规飘字不动**——信息层已磨好，重读数只做增量不做替换；不搞「所有数字都放大」的刷屏方案。
2. **不出转换类遗物/强化**——引擎件只走卡位，永动联动这轮不碰（§二.2.3）。
3. **能量上限不加**——每回合 3 点死工资不变，转换是「挪用」不是「涨薪」；基础能量经济本身不动。
4. **拖拽不做长按/二次确认**——取消路径三条已够，确认弹窗是交互倒退。
5. **刷牌引擎不进教学**——首遇提示兜底（转换卡首遇各一条），教学保持 9 步红线（docs/46 惯例）。

### 1. §一 重读数：事件级大字飘字

新增 `stores/battle` 的 `bigFloater` 状态 + `pushBigFloater()`；只订阅事件流，**不碰结算时序**。渲染在 BattleView 的 `.bigfloat`（舞台中轴偏上 `top: 356px`，即敌人区下沿与手牌区之间的焦点带）。

| 档 | 触发（相对口径） | 字号 / 色 |
|---|---|---|
| ① 重创 | 玩家单次受伤 ≥ 自身最大 HP 15% | 88px 血红 `−N` + 短震屏（走既有 shake 链） |
| ② 完全格挡 | 单发被全挡 ≥ 自身最大 HP 15%（且 ≥10 点） | 72px 冰蓝「完全格挡！」 |
| ③ 重击 | 玩家单次造成 ≥ 目标最大 HP 30%（且 ≥12 点） | 80px 锈金 `−N` |
| ④ 致命 | 在精英 / Boss 节点击杀 | 96px 描金「击溃」 |

- **阈值一律相对**（§一 口径）：act1 的 20 与 act2 的 20 不是一回事。两个绝对值（10 / 12）是按「取严不取宽」加的**下限护栏**，不是主口径。
- **防刷屏**：同屏只留一条；连续重读数间隔 ≥0.4s。抢不到大字的那一击**回落成常规飘字**（绝不少报伤害）；触发了大字的那一击**不再重复报小字**（「格挡！」同理）。
- **三档联动**：`off` 关闭；`simple` 保留文字（震屏本来就只在 `full` 档生效）；`full` 文字 + 震屏。
- 停留 1.2s（常规飘字 0.9s）；`skip()` 会一并清掉重读数，跳过动画不留残影。

### 2. §三 拖动取消

**问题定性**：原来 `pointerup` 不看落点直接 `playCard`——无目标卡拖到哪都打出去。这不是「缺取消按钮」，是**落点判定根本没做**。

| 项 | 实现 |
|---|---|
| 合法落点 | 目标卡（`store.needsTarget()`，复用 core 的 `validatePlayCardState` 口径）：松手命中存活敌人才结算；无目标卡：必须落在战场（舞台矩形内、且不在 UI 面板上） |
| 取消路径① | 拖回手牌区松手 → 取消，手牌区虚线描边 + 「松手取消」提示 |
| 取消路径② | 拖动中 **ESC** 或**右键** → 立即取消（ESC 不会再被设置页抢走） |
| 取消路径③ | 松手在任何非合法区（空白 / UI 面板 / 日志上）→ 取消弹回 |
| 拖拽反馈 | 幽灵卡在不可结算位置降为 **50% 透明**（`.drag-ghost.illegal`），进合法落点恢复实色 |
| 弹回动画 | 0.2s 回到手牌原位（CSS transition），无消耗、无日志 |
| 瞄准模式统一 | 轻点选中的目标卡：ESC / 右键 / 点空白处取消（`watch(store.targeting)` + pointerdown/contextmenu） |

### 4. 偏差与备注

1. **「同帧取最大」未按字面实现**：§一 写的是「同帧只出一个重读数（取数值最大者）」。当前是**逐事件即时判定 + 0.4s 间隔**（先到先得），因为飘字与事件一一对应——若把决策推迟到帧末，同帧的小飘字就来不及回落，反而会丢伤害数字。可观察行为一致（同时只出一条、间隔 ≥0.4s、未中选者回落小字）。
2. **🔧 顺手修掉一个实机可见的旧 bug**：状态提示框的水平定位把 `left` 当成了**左边缘**，而样式是 `translate(-50%)`（中心锚点）——贴近屏幕左侧的状态芯片会把提示框推出视口，文字被切掉一半。已改成按**半宽**夹取，`left` 的语义明确为中心；新增两条单测钉住左右贴边。
3. **震屏口径**：§一 说「重创 + 短震屏」。既有实现对**每次**受到伤害都会 `shake += 1`，但只有 `battleAnim = full` 才真的震——本批没有改动它，所以 full 档下重创的震屏与普通挨打是同一套，未做「重创才震」。若要区分，需要另一个开关，请裁。

> 另：dev server 的 CSS 转换缓存在本批出现过一次陈旧（改动后 `font-size` 仍是旧值），**重启 dev server 即恢复**——与 docs/48 记录过的现象一致，不是代码问题。

## 程序执行记录 · F2 六张转换卡（2026-10-07）

按 §四「F2（内容层）」执行。**引擎侧有一处小增补，见偏差 1。**

### 1. 六张卡（§二.1 逐条落地）

| 职业 | 卡 | id | 费 | 基础 → 升级 | 代价 |
|---|---|---|---|---|---|
| 血械 | 血涌 | `bloodsurge` | 1 | 能量 +1、抽 1 → 能量 +2、抽 1 | 卖 2 血（common） |
| 血械 | 祭血狂热 | `bloodfrenzy` | 2 | 抽 2 → 抽 2 | 卖 3 血 → **升级减到卖 2 血**（uncommon） |
| 炉心 | 回压阀 | `backpressure_valve` | 1 | 能量 +1、抽 1 → 能量 +2、抽 1 | **消耗 2 充能**（uncommon） |
| 炉心 | 齿轮过驳 | `gearbox_transfer` | 0 | 抽 1 → 抽 2 | **消耗 1 充能**（common） |
| 锈语者 | 锈蚀代谢 | `rust_metabolism` | 1 | 污染 +6、抽 2 → 污染 +5、抽 2 | 污染自增（uncommon） |
| 锈语者 | 污能转化 | `toxic_transmutation` | 0 | 污染 +5、能量 +1 → 污染 +4、能量 +1 | 污染自增（common） |

升级口径沿用 docs/50 惯例：**获取量不随升级膨胀**，升级只减代价或加副收益——祭血狂热降血契、锈蚀代谢/污能转化降污染、血涌/回压阀提能量（§二.1 明说能量净增封顶 +1 是唯一破例）。

### 2. 引擎增补（偏差 1）

**§二.1 只给了效果，没给机制**，而「消耗 2 充能」用现有效果表达不了——`spendCharge` 的语义是**消耗全部充能、按每点结算**（泄能重锤/泄压阀/紧急泄压那一路），不是固定成本。若硬用 `spendCharge`，玩家 5 点充能会被一次清空，且「抽 1」会变成「抽 5」。

所以按**既有 `bloodCost` 的同构件**补了一个卡级资源代价：

| 项 | 内容 |
|---|---|
| `CardDefinition.chargeCost?: number` | 打出前的固定充能代价；不足则打不出去（与能量/血量同待遇） |
| `CardUpgrade.bloodCost?: number` | 升级减血契代价（祭血狂热要的那一档）；此前升级只能改费用/效果/关键词 |
| 校验 | `validatePlayCard`：`chargeCost > 充能` → 拒绝理由「充能不足（需要 N，当前 M）」；失败零改动 |
| 支付 | `playCard` 通过校验后扣充能并 emit `ChargeChanged`（日志/UI 同源） |
| 卡面 | `CardView` 新增冷色「充能 N」角标（与暖色「血契」角标同构，两者同时在时自动下移一行）；手牌/拖拽幽灵/奖励三选一/升级页/图鉴 5 处全挂 |

**注意区分**：`chargeCost`（固定成本，付不出就打不出）≠ `spendCharge`（消耗全部，按每点结算）。两者各自保留，不合并。

### 4. 偏差与追问

1. **`chargeCost` 是程序补的机制**（§二.1 只列了效果）。它和 `bloodCost` 完全同构、零新概念，但如果策划本来想的是「消耗全部充能」那种，请说一声——改法是两张卡各换一个效果，不用动引擎。
2. **祭血狂热的「升级减血契」需要 `CardUpgrade.bloodCost`**。这条顺带把「升级减代价」从费用扩到了资源代价；如果不想扩，替代方案是升级只加抽牌数（会跟 docs/50 的升级惯例相悖）。
3. **`bloodrite`（0 费卖 1 血换 1 能）与 `rustcommunion` 未动**（§二.3 明确「补槽位不替代」）。注意血涌与 bloodrite 挨得比较近：血涌 1 费卖 2 血换 1 能 + 抽 1（净能 0），bloodrite 0 费卖 1 血换 1 能（净能 +1）——前者买的是**牌**，后者买的是**能**，分工清楚。
4. **观察清单新增**（§四要求）：刷牌引擎强度 / 无限组合排查——真人实测时重点问「有没有一把牌打不完的感觉」，护栏五条见 §二.2，出现无限组合先调稀有度或代价、不改机制。

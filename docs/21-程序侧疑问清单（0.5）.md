### Q2. 🔴 P3 门禁第二条：存档 version + migration，当前存档没有版本号

- **现状**：`systems/save.ts` 只按槽位存 JSON，**没有 version 字段与迁移链**。P3 门禁写着「存档兼容（version + migration）」，P6 的 meta/难度也要求「migration 链每动一次必须有往返单测」。
- **疑问**：0.5 是否现在就把存档结构升级为 `{ version, data }` + 迁移函数链？还是等 P6 与 meta 一起做一次？
- **程序的担心**：P5「继续远征」与 P6 难度都要动存档，越晚引入版本号，要迁移的存量档越多。建议**现在引入 v1 + 迁移框架**，后续每次改结构只加一个迁移函数。

> **⚠️ 程序更正（2026-10-05）：本题前提写错了。** `src/systems/save` **0.1 起就有** `{ version, data }` 信封 + `migrations` 迁移链（ADR-008「第一天就实现」）。真正缺的只有两点：①「无信封裸档」此前会被 `migrate()` 丢弃；②新增字段的迁移。docs/23 §2 已确认，程序已补：`migrate()` 把无信封对象按 v0 处理并保留，`SCHEMA_VERSION 1→2`（1→2 只对进度档补 `recastUsedNode`，设置档不受污染），并补 2 例往返测试。

## 二、口径确认（不阻塞，但想按策划口径定稿）

### Q3. 「本场所有攻击 +1」的粒度
实现现状：修正在**每一次伤害结算**上加 +1（多段攻击=每段各 +1）；同名卡重复打出会叠加（两次血锈光环 = +2）。
- a) 每段 +1（现状，推荐：与「力量」口径一致） / b) 每张攻击牌只 +1 一次 / c) 不允许叠加。

### Q4. 反向确认：血锈光环**不**影响反伤
实现现状：反伤（荆棘血痂）是**固定伤害**，不吃力量/充能/易伤，也**不吃血锈光环**。
- 是否符合预期？「所有攻击 +1」如果被理解成「包括反伤」，请指出。

### Q5. 「血怒」的取整口径
实现现状：乘区后**每段单独取整**（管线规定「乘区后一次取整」）。因此同一张牌：
- 单段：9 ×1.5 = 13.5 → **14**
- 与低血沸腾同槽拆三段：3/3/3 各 ×1.5 = 4.5 → 5/5/5 = **15**（比单段多 1 点）
- **疑问**：接受每段取整（会因拆段多赚 1 点），还是要求「整卡一次取整」（会与「每段独立、独立触发」的现有实现冲突）？建议接受现状并写进卡面说明。

### Q6. 重铸的池子与边界（docs/16 P3.4）
实现现状与需确认点：
1. 随机池 = **同 tier + appliesTo 含该卡 + 排除全局已持有**（沿用「同一强化全局唯一」）。
2. **排除被移除的那一枚**（不允许原地换回）。
3. 同阶池为空时：**只移除、不补**（当前行为）。是否改为「禁止重铸」或「允许补它自己」？
4. HP 消耗：`HP ≤ 5` 时**禁止重铸**（不能把自己换死）。是否允许降到 1 HP 也要换？
5. 每座祭坛限 1 次：已实现（按节点判定）。

### Q7. 休息点「移除一张卡」的次数与边界
实现现状：休息点仍是**三选一**（憩息 / 打磨 / 剔除），选了任一选项即离开；卡组**至少保留 1 张**，不能清空。
- 是否需要「一次移除多张」或「休息点可同时回复+移除」？

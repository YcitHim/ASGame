## 第一部分 · P4 剩余输入（5 项）

### ① 预告型高伤数值表（docs/16 §4.2）

**为什么需要**：docs/16 要求「预告型高伤单发（15+）进敌人意图表，至少 1 只小怪 + 看守/锈喉补招」。docs/27 提到它是把胜率往下压的杠杆，但没有给具体数值。
**交付格式**（每只怪一行）：

~~~
敌人 id | 新增/修改哪一招 | charge 值 | 预告回合数 | 释放伤害 | 权重 | 触发条件
~~~

**程序若不收到**：会按下述临时值实现并标「临时·待策划追认」，复跑后再报（可覆盖）：蚀肉锈虫群或锈蚀猎犬 加「蓄 1 回合 → 16」；铁锈看守「蓄 2 → 20」；锈喉补一招「蓄 1 → 18」。

### ② 格挡收益卡设计（docs/16 §4.3）

**为什么需要**：docs/16 要求「格挡附带收益卡 1~2 张（如「格挡时获得充能」）」，docs/27 §二只给了 5 张副线卡，未含此项。
**注意**：这会引入一个新触发器钩子 onBlock（格挡获得时触发）；程序侧已有注册制与队列，成本可控。
**交付格式**（1~2 行）：

~~~
id | 名称 | type | rarity | cost | 效果（含触发时点） | 升级版 | 机制卡: 是/否
~~~

### ③ 遭遇池轮换设计（docs/16 §4.5）

**为什么需要**：docs/16 要求「普通战不再固定组合，铁锈傀儡（rust_sentinel）进池；同种子同遭遇」，但组合与权重未给。现状：n1 固定「猎犬+布道者」、n2 固定「虫群+重装兵」。
**交付格式**：每个普通战节点的候选组合（1~3 组）+ 组内权重 + rust_sentinel 进哪个节点。
例：n1 = [猎犬+布道者] 权重 4 / [虫群+哨兵] 3 / [重装兵单只] 3

**程序若不收到**：会按上例的临时组合实现并标注，复跑后再报。

### ④ 结算情境化文案（docs/16 §4.6 的一部分）

**为什么需要**：docs/16 §4.6 的文案批 = flavor 30+（已给 33 条）+ Boss 台词 3 句（已给）+ 结算情境化文案（未给）。
**交付格式**：战斗胜利 / 战斗失败 / 精英战胜利 / Boss 战胜利 / 远征失败，各 1~2 句。现有占位：「锈蚀回廊的敌人已被肃清。」「血肉归还于锈。」

### ⑤ 卡面 flavor 位的 UI 基准修订确认（程序侧改动，需你点头）

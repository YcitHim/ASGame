## 2. 待办 · 架构与一致性（不影响当前体验）

### D-1 · ADR-002 栈式队列未接入实战结算 【0.5 P1 已解决】
- **位置**：`core/pipeline/effect-queue.ts`（实现+单测齐全）；`core/combat/resolve.ts` / `reducer.ts`（实际走直接函数调用）。
- **证据**：全仓 grep，`EffectQueue / removeByUnit / buildMultiHitEffects` 无任何生产调用方；`UnitDied.clearedEffects` 恒为 0；docs/03 §4 决策 2「反噬动作压入栈式队列」同样是悬空约定。
- **为什么现在不动**：0.1 没有任何连锁内容（反伤 / 亡语 / 多敌互触发），改成队列只增风险不增产出。
- **建议**：正式修订 ADR-002，写明「0.1 结算走直接调用；**0.5 引入连锁内容前必须接入队列**」。
  - 接入后只要没有挂起动作，`clearedEffects` 仍为 0，**事件序列不变**，S6 录的 golden replay 不会因此失效；一旦 0.5 加了连锁内容，本来就要重录基线。
- **解决（0.5 P1，2026-10-05）**：`Draft.queue` + `enqueueEffects` / `drainQueue` / `killUnit` 已接入；`tests/unit/effect-queue-combat.spec.ts` 断言 `clearedEffects` 真实非 0（首段击杀多段 → 2）；三盘 golden 哈希未变。详见 docs/16 P1 执行记录。
- **备选**：S6 直接接入（约 1 天，并需重跑全部战斗回归）。

### D-2 · modifyCard 改不了费用 / 卖血 / 关键词
- **位置**：`core/registry/enhancement-handler.ts` 的 `ModifyCardResult` 只有 `effects / play`。
- **影响**：装配不出「减重（费用 -1）」「节油血契（卖血 -1）」这两枚 T1 强化，强化池 3/4。
- **修复**：Result 增加 `costDelta / bloodCostDelta / keywords` 覆盖，并在 `effectiveCardWithEnhancements` 合并（费用需重走 `evaluateValue("cardCost")`）。
- **工作量**：约半天（含单测）。费用类强化上线前要确认 `cardEnergyCost` 能读强化后的费用。

### D-3 · 强化加成绕过修饰符管线（`layer:"enhancement"` 不可追溯）
- **位置**：`core/registry/enhancement-handler.ts`（empower/fortify 直接改 `effect.value`）。
- **影响**：`DamageDealt.layers` 看不到强化层，违背 ADR-003「每层可追溯」；门禁 3 的「用日志定位修饰层」在强化场景失效。**最终伤害数值与走管线一致，当前玩家体验无差异。**
- **修复**：empower/fortify 产出 `{ layer: "enhancement", op: "add" }` 的 Modifier，由 `resolveEffects → dealDamage(args.modifiers)` 注入。
- **工作量**：约 1 小时 + 单测。

### D-4 · Buff 时长硬编码 2
- **位置**：`core/combat/resolve.ts` 的 `applyBuffToTarget(..., effect.stacks ?? 1, 2)`。
- **影响**：所有施加减益/增益固定 2 回合，内容无法表达 1 或 3 回合。**当前默认仍是 2，行为不变**，故不影响现阶段体验。
- **修复**：`applyBuff` effect schema 增加 `duration`，缺省读 Buff 定义默认值。
- **工作量**：约 30 分钟 + 单测。

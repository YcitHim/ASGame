# 46 · 状态扩展设计「九相」——诅咒真机制落地

> 整理：策划 · 2026-10-07
> 缘起：甲方交付 8 个新状态方向的灵感稿（胆怯/虚弱/荆棘/坚韧/眩晕/分裂/冰缓/灼烧/颠倒——实为 9 个，本文按 9 个设计），要求「既能用在玩家身上也能用在怪物身上，融入游戏」。
> 定位：本文即 docs/45 Q1 所要求的**诅咒真机制设计稿**。自本文起，「诅咒」从禁用词变成正式机制类别；v1.0.x 的 UI 仍统一「异常」（docs/45 Q1 裁决不变），诅咒类别随 v1.1 沉没圣堂落地。
> 结构：§一 分类总纲 / §二 与现有机制的合并裁决（虚弱·易伤·反伤三套旧账）/ §三 九相逐条定稿 / §四 双向语义表（玩家⇄怪物）/ §五 交付面（敌人·卡牌·遗物·事件）/ §六 工程触点 / §七 分期与门禁

## §一 分类总纲：状态从此分三类半

甲方原稿的 9 个效果不是一锅粥，按作用方式分成三类半——这个分类就是落地框架：

| 类别 | 成员 | 作用方式 | UI 称谓 |
|---|---|---|---|
| **异常**（数值类减益） | 胆怯、虚弱、灼烧 | 改数值：承伤/造伤/生命上限 | 异常 |
| **诅咒**（规则类减益） | 冰缓、颠倒、眩晕 | 改规则：费用/随机/行动权 | **诅咒**（新类别，v1.1 启用） |
| **加持**（增益） | 荆棘、坚韧 | 反弹/维续格挡 | 加持 |
| **亡语**（死亡触发） | 分裂 | 死亡时触发 | 不进状态栏，写进敌人档案 |

这样归类的红利：
1. **「诅咒」终于名副其实**——玩家从反馈 10 开始念叨的「诅咒」，指认的就是「敌人对我做的怪事」里最邪门的那部分。改规则的三个（冰缓/颠倒/眩晕）配这个名，数值类的留在「异常」。UI、词条、意图标签按类别分色分图标。
2. **意图标签有类别可挂**（docs/41 已改实际减益名）：敌人要挂诅咒时，意图副标显示「诅咒 · 冰缓」这一级，不再笼统。

**持续模型（铁律修订，docs/14 Q12 口径更新）**：减益参数不再只有「剩余回合数」一型，正式扩为两型——

| 类型 | 参数 | 衰减 | 用于 |
|---|---|---|---|
| 计时型 | 剩余回合数 | 回合开始 −1 | 旧口径（现有 易伤/虚弱/蚀锈 等） |
| **层级型** | 层数 | **不衰减，战斗结束清零** | 新九相中的 胆怯/虚弱/荆棘/坚韧/灼烧 |
| 层数计时型 | 层数 = 剩余回合 | 回合开始 −1 层 | 冰缓/颠倒（甲方原案「每回合减少一层」） |

甲方原稿的「关卡结束后清零」与现状天然一致（战斗 buff 战斗结束即清），无需新机制，只需明确「关卡 = 一场战斗」。**所有九相、两侧通用：任何状态都活不过一场战斗。**

> **回写注（2026-10-07，依 docs/58 §六-2 甲方拍板）**：「层级型为九相专用」这一原裁定**开了一个口子**——职业特性「玻璃大炮」引入的新减益 **超负荷 `overload`**（affliction / 层级型 / 不衰减、战斗结束清零）同样走层级型。
> 它的两条结算不在九相表内：① 获得时立即受 2 点伤害（在 `changeCharge` 里结算）；② 每张卡获得的格挡 −1（走 `block` 修饰管线）。
> 除 `overload` 外，本表仍是层级型的完整名单；后续若再开新的层级型减益，同样在此登记。

## §二 与现有机制的合并裁决（先还旧账，再添新账）

甲方稿里有三个名字撞了现有机制。裁决原则：**新概念是旧概念的严格泛化就合并，不留两套近似机制。**

### 2.1 虚弱：采用甲方层数模型，旧计时型退役

| 项 | 旧（现役） | 新（定稿） |
|---|---|---|
| 模型 | 计时型：造伤 ×0.75，回合开始 −1 层 | 层级型：**每层造伤 −10%，上限 5 层**，不衰减，战斗结束清零 |
| 换算 | 旧「虚弱 N 回合」→ 新「虚弱 3 层」（−30%，比 ×0.75 温和但可续叠） | — |

- **断链规则（docs/38 §三 C-1）同步映射**：蓄力中的敌人被施加**任意层数**虚弱或胆怯即断链，规则本体不变，只换引用的 buff id。
- 触点（程序对账）：`resolve.ts` 的 ×0.75 修饰、全部施加 weak 的卡牌/敌人/强化、`buffs/definitions.ts`、glossary、断链规则、相关 golden。

### 2.2 易伤 → 胆怯：合并，「易伤」名词退役

| 项 | 旧（易伤） | 新（胆怯） |
|---|---|---|
| 模型 | 计时型：承伤 ×1.5 | 层级型：**每层承伤 +10%，上限 5 层（+50%）**，不衰减，战斗结束清零 |
| 换算 | 旧「易伤 N 回合」→ 新「胆怯 3 层」（+30%） | 上限恰好对齐旧 ×1.5 的上限感 |

- 留两套「承伤加深」是纯粹的冗余，合并。换算后数值略低于旧 ×1.5，属预期内的温和化，sim 复跑验收（门禁见 §七）。
- 触点：全部施加 vulnerable 的卡牌（含 T1 强化「淬锈」onHit）/敌人/事件、`resolve.ts` ×1.5 修饰、断链规则、glossary、i18n。**「淬锈」类 onHit 强化改为「命中施加 1 层胆怯」——多段攻击从「只刷新回合」变成「真能叠层」，这是有意的加强，列入 sim 观察项。**

### 2.3 反伤 → 荆棘：合并，层数化

| 项 | 旧（反伤 thorns） | 新（荆棘） |
|---|---|---|
| 模型 | stacksAndTurns：stacks=固定伤害值，2 回合 | 层级型：**每层反弹 3 点，上限 5 层（15 点）**，不衰减，战斗结束清零 |
| 换算 | 旧「反伤 X 点」→ 新「荆棘 ⌈X/3⌉ 层」 | — |

- 铁律继承：荆棘伤害**不吃力量/充能/胆怯/虚弱，不被荆棘再反弹**（现 `resolve.ts` 的反伤豁免规则原样沿用）。
- **多段攻击逐段触发**（现状如此，明确保留）——荆棘是多段攻击者的天敌，这个克制关系是设计资产。
- 触点：荆棘血痂等反伤来源、`resolve.ts` 反伤管线、glossary「反伤」词条替换为「荆棘」。

### 2.4 三套旧账的处理顺序

合并 = 改既有数值与规则，**严格走数值改动铁律**：sim 复跑（30%~70% 健康，期望 45%~60%）+ golden replay 随改随录 + 真人实测。三套合并在 §七 的 Phase 1 一次做完，只录一次 golden。

## §三 九相逐条定稿

> 统一规则：战斗结束全部清零；同名状态重复施加 = 层数累加（受上限截断），除注明外。「层」在 BuffRow 显示层数，图标与配色按 §一 类别分。

### 3.1 胆怯（异常）——见 §2.2

每层承伤 +10%，上限 5 层。双向通用。

### 3.2 虚弱（异常）——见 §2.1

每层造伤 −10%，上限 5 层。双向通用。

### 3.3 荆棘（加持）——见 §2.3

每层反弹 3 点固定伤害，上限 5 层，逐段触发。双向通用。

### 3.4 坚韧（加持）

| 项 | 规格 |
|---|---|
| 效果 | 每层使持有者在**回合开始获得 3 点维续格挡**（不随回合清零，联动 docs/41「维续」词条） |
| 层数上限 | **3 层**（9 点/回合） |
| 累积保险丝 | 维续格挡总量**累积上限 25**——到顶不再涨。这是防死锁的硬保险：无上限的永续格挡会把战斗拖成互瞪，必须掐死 |
| 清零 | 层数与维续格挡都在战斗结束清零 |
| 克制关系 | 怕多段低伤（格挡被逐段磨掉）不如怕「不打」——对手停手等它自然…它不自然衰减，所以坚韧持有者的正确对策是**灼烧/胆怯这类绕过格挡的手段**，克制链见 §四 |

### 3.5 眩晕（诅咒 · 控制）

| 项 | 规格 |
|---|---|
| 效果 | 下一整回合不可行动：玩家 = 不可出牌（可结束回合）；敌人 = 跳过行动且**意图清空** |
| 叠加 | 不可叠加；持续中重复施加 = 无效（不刷新） |
| 对玩家来源 | **仅限精英/Boss，且必须提前一回合在意图里预告「眩晕」**——玩家被无预警跳过回合是本作允许的最强挫败，无预警即设计事故 |
| 对敌人来源 | 玩家卡牌仅稀有卡持有；**精英/Boss 有「眩晕抗性」：首次被眩晕后，本场战斗免疫后续眩晕**（给一次、不贪第二次） |
| 断链互动 | 眩晕蓄力中的敌人 = 断链 + 空转（比虚弱/胆怯更硬的中断，与之同族不冲突） |

### 3.6 分裂（亡语）

| 项 | 规格 |
|---|---|
| 效果 | 持有者死亡时，原地召唤 1 只 **15 HP 的寄生体**（act2 新敌人，见 §五） |
| 叠加 | 不可叠加，一只怪物至多带一层 |
| 适用侧 | **敌方限定**。玩家侧「死亡后分裂」在肉鸽里等于没有（玩家死亡 = 局终），不硬凑双向——这是「九相双向」原则的唯一例外，明示在此 |
| 数值 | 寄生体 15 HP 为初稿，进 act2 敌人表时按层数位置微调 |

### 3.7 冰缓（诅咒 · 规则）

| 项 | 规格 |
|---|---|
| 对玩家 | 所有手牌（攻击/技能一视同仁）**费用 +1**，层数 = 剩余回合，回合开始 −1 层，**归零后费用立即恢复原价**（修饰管线动态求值，不污染牌面数据） |
| 对敌人 | 敌人没有能量——映射为**造成伤害 −20%**（行动被冻得迟滞），层数衰减规则同上 |
| 上限 | 3 层（对玩家 = 3 回合 +1 费；对敌人 = 3 回合 −20%） |
| 费用地板 | +1 后费用仍向下取整为 ≥0？不，**费用没有地板问题**（只会变贵）；但要处理「+1 后打不起」的实况——UI 费用数字即时刷新为红色 |

### 3.8 颠倒（诅咒 · 规则）

| 项 | 规格 |
|---|---|
| 对玩家 | 层数 = 剩余回合。生效期间**每回合开始，手牌费用重新随机为 0~3**（原费用被覆盖，归零后恢复）。随机走 `rng.stream("curse")` 新流，不污染 combat 流，可复现 |
| 对敌人 | 意图数值在预告时随机化为 **原值的 50%~150%**（同流），意图显示为「?」——玩家知道它疯了，但不知道疯成什么样 |
| 上限 | 2 层 |
| 设计定位 | 这是九相里最「活」的一个：对玩家是灾难也是赌局（0 费神抽），对敌人是读招系统的压力测试。v1.1 的招牌诅咒 |

### 3.9 灼烧（异常 · 特殊）——**对甲方原案有一处修改**

| 项 | 甲方原案 | 本文定稿 | 修改理由 |
|---|---|---|---|
| 上限扣除 | 每回合 −1 生命上限/层，**不可恢复** | 战斗内每回合 −1 上限/层；**战斗结束时上限恢复，已损失的当前 HP 不补** | 跨战斗永久扣上限 = 死亡螺旋：一场没处理好的灼烧让整局报废，而玩家**没有任何反制手段**（本作无净化）。保留战斗内的压迫感，去掉局外的残废感 |
| 层数 | 可叠加 | 上限 5 层，回合开始每层扣 1（上限 5/回合） | — |
| 双向 | 双向 | 双向（敌人同样有生命上限，烧 Boss 上限是锈语者系的浪漫） | — |
| 预案 | — | 若真人实测喊「不够狠」：改为战斗结束上限只恢复一半。预案冻结在此，不另开裁决 | — |

## §四 双向语义与克制链

### 4.1 双向语义总表（「既能给玩家也能给怪物」的精确口径）

| 状态 | 用在玩家 | 用在敌人 | 双向同构？ |
|---|---|---|---|
| 胆怯 | 承伤 +10%/层 | 同 | ✅ 完全同构 |
| 虚弱 | 造伤 −10%/层 | 同 | ✅ 完全同构 |
| 荆棘 | 受击反弹 3/层 | 同（玩家打它也被弹） | ✅ 完全同构 |
| 坚韧 | 回合开始 +3 维续格挡/层 | 同 | ✅ 完全同构 |
| 灼烧 | 回合 −1 上限/层 | 同 | ✅ 完全同构 |
| 冰缓 | 手牌费用 +1 | 造伤 −20%（无能量可冻，冻行动） | ⚠️ 映射 |
| 颠倒 | 手牌费用每回合随机 0~3 | 意图数值随机 50%~150% | ⚠️ 映射 |
| 眩晕 | 不可出牌 1 回合 | 跳过行动 1 回合 | ✅ 同构，规则各异（§3.5） |
| 分裂 | —（不适用） | 死亡召唤 15 HP 寄生体 | ❌ 敌方限定 |

### 4.2 克制链（设计给玩家看的「解法」）

```
坚韧（永续格挡）──被──▶ 灼烧 / 胆怯（绕过或放大真实伤害）
荆棘（反弹）    ──被──▶ 眩晕 / 冰缓（少打、晚打，反弹自然落空）
分裂（亡语）    ──被──▶ 留 AOE / 控制击杀节奏（别让两只同时裂）
敌方诅咒三件套  ──被──▶ 坚韧 / 速杀（规则扭曲只烦活人，死人不被烦）
```

这条链不进游戏内文案，是敌人配置与卡牌发放的**平衡罗盘**：每个给玩家上状态的敌人，玩家的卡池里必须有对应解法的影子。

## §六 工程触点（给程序的边界）

1. **buff 注册**：9 个新 id 入 `core/registry/ids.ts` 与 `buffs/definitions.ts`；层级型用既有 stacks（无 duration）表达，层数计时型沿用 stacksAndTurns（蚀锈先例）。**无新数据结构**。
2. **修饰管线**：冰缓/颠倒走 `cardCost` 求值点（管线已有该 layer，play-card.ts:62 在案）；虚弱的造伤修饰、胆怯的承伤修饰替换旧 ×0.75/×1.5 两个硬编码点。
3. **RNG**：新增 `curse` 流（颠倒专用），不进 combat 流；同种子可复现，golden 兼容。
4. **行动权**：眩晕 = 玩家侧禁出牌标记 + 敌人侧意图清空/跳过，均走事件（`Stunned`），不动结算顺序。

## 程序执行记录：颠倒 / 冰缓的判定时点修复（甲方 2026-10-07）

甲方反馈：「怪物诅咒颠倒对角色不生效啊，我看卡牌没有变化，状态栏也没有这个诅咒」。

### 根因：玩家回合开始递减造成的差一
`resolveCurses` 原本在**玩家回合开始**统一处理两侧的灼烧 + 冰缓/颠倒递减。敌人是在**敌方回合**给我挂上颠倒的，
于是下一次玩家回合一开始：`1 层 − 1 = 0` → 当场移除。玩家从头到尾没见过这条诅咒：
- 状态栏看不到（BuffExpired 发生在渲染之前）
- 卡牌费用没变化（`rollReverseCosts` 在回合开始读层数时已经是 0）

### 修法：层数 = 剩余回合，在**受影响单位自己的回合结束**递减
- 新增 `decayTimedCurses(sink, units)`，把冰缓/颠倒从 `resolveCurses` 里摘出来；
  `resolveCurses` 只留灼烧（每回合扣上限，保持玩家回合开始结算）。
- 调用点两处：玩家 `EndTurn`（`TurnEnded` 之前）、敌方回合结束（`runEnemyTurn` 之后）。
  ——谁挂的不重要，重要的是「挂上之后至少要活过对方一整个回合」。
- 顺带补上：**回合内抽到的牌也吃随机费用**（`drawCards` 末尾 `rollReverseCostsForNewCards`）。
  原先只在回合开始给当时的手牌掷费用，抽牌流的构筑能顺手把诅咒绕过去，等于只罚了一半的手牌。

### 回归用例（已自证会红）
`tests/unit/p28-reverse-curse.spec.ts`，4 条，全部走「敌人钉意图 → 挂到我身上」的真实路径：
1. 敌人挂的 1 层颠倒必须活过玩家一整个回合：状态栏能看到、手牌每张费用都在 0~3、
   UI 预览 = `reverseCosts` = 实付能量；本回合结束才归零移除。
2. 2 层颠倒撑两个自己的回合（每回合结束 −1）。
3. 玩家给敌人挂的颠倒同样在敌方回合结束递减（谵语 2 层）。
4. 回合内抽到的牌也拿到随机费用。

**自证**：把旧的「玩家回合开始递减」临时加回去，4 条用例全红（第一条直接报「expected undefined to be 1」，
即诅咒在玩家出手前就没了）；改回后全绿。

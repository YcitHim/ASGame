## §三 获取与池子规则（现行）

| 渠道 | 池子 | 抽几件 | 实现 |
|---|---|---|---|
| 开局身份件 | 职业 `startRelics`（无 tier） | 固定 | `data/classes/*.json`；validator 拒绝「带 tier 的件写进 startRelics」 |
| 首胜随身遗物 | T1 | **固定 3 件**（不受难度影响） | `run.companionRelicChoices()`；第一场战斗胜利后由 RewardView 弹出，一局一次 |
| 精英 / 残骸锻核 | T2 | 普通 3 / 锈蚀 2 | `run.relicChoices([2])`；难度参数见 `DIFFICULTY_PARAMS` |
| Boss | T3 | 普通 3 / 锈蚀 2 | `run.relicChoices([3])` |
| 事件 | T1 + T2 混合 | 事件自定 `count`（缺省 1） | `event.ts` 的 `gainRelic`；身份件不入池 |
| 当铺类事件 | 可典当池 = T1 + T2 − 身份件 | 事件自定 | `loseableRelicPool()`；**身份件永不被当**（docs/54 E4） |

**共同规则**

1. **不可重复持有**：所有抽取都先剔除本局已持有的遗物（`rollRelicChoices` 的 `taken`）。
2. **同种子同结果**：掉落走 `reward` RNG 流，种子由 `run.seed` 与本层序号派生。
3. **解锁过滤**：`unlockCondition` 未解锁的件不入任何池（`isContentAvailable`）。
4. **锈蚀难度的二选一**只作用于精英 / Boss 掉落；首胜随身遗物始终三选一（甲方 2026-10-07 反馈）。
5. 遗物效果按 `timing` 派发；`once` 决定整场一次 / 每回合一次 / 每次都触发。

## §四 机制速查（写新遗物设计时可用的积木）

### 4.1 触发时机 `timing`

| 值 | 何时派发 | 现有用例 |
|---|---|---|
| `onBattleStart` | 战斗开始（开场状态挂好之后） | 大部分 T1/T2 |
| `onTurnStart` | 玩家回合开始 | 红泪戒指 / 锈蚀护符 / 唱诗班电池 |
| `onTurnEnd` | 玩家回合结束 | 第三捧灰 / 圣油灯 / 炉心 |
| `onPlay` | 每打出一张牌 | 齿轮币 |
| `onHit` | 攻击命中时 | 飞锈（卡牌能力） |
| `onSell` | 卖血（血契代价结算）后 | 血泵心脏 / 血齿轮 |
| `onBlock` | 获得格挡时 | 动能电池（卡牌能力） |
| `onGainCharge` | 获得充能时 | 飞升齿轮（卡牌能力） |
| `onPollutionMax` | 污染即将触顶、反噬判定前 | 九十九（卡牌能力） |

### 4.2 次数限制 `once`

| 值 | 含义 |
|---|---|
| `battle` | 整场战斗只触发一次，进入战斗时清账 |
| `turn` | 每回合只触发一次，回合开始清账 |
| 缺省 | 该 timing 每次派发都触发（谨慎：`onPlay` 不写 once 会每张牌都触发） |

### 4.3 常用效果 `effects[].kind`（遗物现用到的加粗）

| kind | 语义 |
|---|---|
| **damage** | 造成伤害；`target` 选目标，`hits` 多段 |
| **block** | 获得格挡 |
| **heal** | 回复 HP |
| **draw** | 抽牌 |
| **applyBuff** | 挂 Buff（`strength` 力量 / `timid` 胆怯 / `weak` 虚弱 / `regeneration` 再生 等） |
| **gainCharge** | 增减充能 |
| **gainPollution** | 增减污染（负数 = 减少） |
| `gainEnergy` | 增减能量 |
| `gainModifier` | 写一场临时修饰（`valueKind` + `op`），战斗结束消失 |
| `clampCharge` | 充能封顶：超过 value 时平衡回 value |
| `spendCharge` / `spendPollution` | 消耗全部对应资源，每点按 `mode`（damage/block/draw）结算 |
| `chargeFromEnergy` | 充能 = 当前能量 + value |
| `bankCharge` | 充能储蓄：扣光，下回合还回「扣掉的 + value」 |
| `transferPollution` | 自身污染 −2N，目标敌人 +N 蚀锈 |
| `consumeCorroding` | 兑现目标全部蚀锈，每层追加 value 伤害 |
| `consumeBoons` | 消耗自身全部加持与充能，每层造成 value 伤害 |
| `gainCard` | 生成卡牌进手牌（可 `delayTurns` 延迟） |
| `destroyHand` | 从手牌销毁 value 张（本场移出，战后归还） |
| `summon` | 召唤（亡语用） |

### 4.4 条件 `condition`（可组合）

| 条件 | 语义 |
|---|---|
| `pollutionAtLeast` / `pollutionAbove` / `pollutionBelow` | 污染阈值 |
| `chargeAtLeast` | 充能阈值 |
| `hpBelow` / `hpAtLeast` / `selfHpBelow` / `selfHpAtLeast` | HP 阈值 |
| `cardsPlayedThisTurn` | 本回合已打出牌数 |
| `tookDamageThisTurn` | 本回合（含刚结束的敌方回合）玩家是否受过攻击伤害 |
| `handIsEmpty` | 手牌为空 |
| `hasBuff` / `targetHasBuff` | 身上 / 目标身上有某 Buff |
| `not` / `and` / `or` | 逻辑组合 |

> ⚠️ `tookDamageThisTurn` 的口径（甲方 2026-10-08 已确认）：**卖血也算受伤**（`loseHp` 在 `bloodpact` 原因下置位）。这正是「以血还血」第二段此前不触发的根因。

### 4.5 目标 `target.type`

`self`（自身）· `chosenEnemy`（选定敌人）· `randomEnemy`（随机敌人）· `allEnemies`（全体敌人）· `lowestHpEnemy`（最低血）· `highestHpEnemy`（最高血）

## §五 工程约束（改 JSON 时必须一起过）

1. **每件遗物必须有 name / desc / flavor 三条 i18n**，缺一即 validator 报错（docs/38 §一）。
2. **T1 起始池 ≥6 件**，低于 6 件 validator 直接拦（`validate-content.ts`）。
3. **身份件（无 tier）只能出现在职业 `startRelics` 里**；反过来说，写进 `startRelics` 的件不能带 tier。
4. **tier 只允许 1 / 2 / 3**，schema 是 strict（多写字段会报错）。
5. **效果 / 条件里的 id 必须已注册**（`CONDITION_IDS` / `BUFF_IDS` / `TARGET_IDS` 等），拼错会在 `npm run validate` 阶段拦下。
6. **改数值不需要改代码**；只有新增「效果种类 / 条件种类 / 时机」才需要动 core（同时回写 `content.ts` 类型与 validator 注册表）。
7. 改完必须跑：`npm run validate` → `npm test` → 若影响战斗序列，golden 回放哈希会变，需要 `npm run record:golden` 重新录制并说明差异。

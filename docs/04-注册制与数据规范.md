# 04 · 注册制与数据规范

> 对应 ADR-004 / ADR-005。目标：**新增内容永远不需要改核心代码，且构建期就能抓错。**

## 1. 五类注册表

| 注册表 | 职责 | 示例 |
|---|---|---|
| `condition` | 布尔判定，可组合（and/or/not） | `hpBelow{percent}`、`pollutionAbove{n}` |
| `target` | 目标选择器 | `self`、`randomEnemy`、`allEnemies`、`lowestHpEnemy` |
| `keyword` | 关键词统一钩子接口 | 消耗/保留/虚无/固有/血契/充能/污染/过载/再生 |
| `cardHandler` | 卡牌复杂逻辑（TS 函数，可单测） | `multihit`、`rampageOnSameTarget` |
| `enhancementHandler` | 强化机制逻辑 | `bloodboil`、`bloodrage` |

**纪律：** JSON 里出现未注册 id → 构建期校验直接失败，不允许运行时才炸。

## 2. 卡牌 JSON 模板（v1）

```json
{
  "id": "bloodbolt",
  "class": "bloodwright",
  "type": "attack",
  "rarity": "common",
  "cost": 1,
  "keywords": ["bloodpact"],
  "bloodCost": 2,
  "effects": [
    { "kind": "damage", "target": { "type": "chosenEnemy" }, "value": 9 },
    { "kind": "draw", "value": 1, "condition": { "type": "hpBelow", "percent": 50 } }
  ],
  "upgraded": { "cost": 1, "effects": [{ "kind": "damage", "value": 12 }, { "kind": "draw", "value": 2 }] },
  "i18n": "card.bloodbolt"
}
```

- 复杂机制不用 `effects`，改用：
  `"play": { "handler": "multihit", "params": { "hits": 3, "split": [0.4, 0.3, 0.3] } }`
- 文案一律 i18n key（`card.{id}.name` / `.desc` / `.flavor`），JSON 不写死中文。

## 3. 强化 JSON 模板（修订原方案 §6.4）

```json
{
  "id": "bloodboil",
  "tier": 2,
  "appliesTo": ["bloodbolt"],
  "mutex": ["heavy_single"],
  "handler": "bloodboil",
  "params": { "condition": { "type": "hpBelow", "percent": 50 }, "hits": 3, "split": [0.4, 0.3, 0.3] },
  "i18n": "enh.bloodboil"
}
```

- 强化通过**三个**挂载点生效：`modifyCard`（出牌前改形态）/ `onHit`（命中计数）/ `onKill`（此牌击杀敌人时，docs/25 §1「血偿」）。
- 机制逻辑在 `enhancementHandler` 里，JSON 只传参。
- **机制卡集合（docs/25 §2 防再犯规则）**：
  1. `机制卡集合 = 当前全部强化的 appliesTo 并集`，由数据推导，**不单独维护清单**；
     `lighten / rustbite / bloodwage` 的 appliesTo 就是这样推导的（含 `overloadstrike` / `plaguesurge` 这类"效果即机制、无 keywords 字段"的牌）；
  2. **今后新卡设计表必须显式标注「机制卡: 是/否」**，策划填表时定死，程序照抄，不再反推；
  3. 新强化铺量时，`appliesTo` 直接用「机制卡集合 ± 显式排除/包含」描述。
- **`modifyCard` 返回值（2026-10-05 扩展）**：`effects / play / keywords / modifiers`。
  其中 `modifiers` 是 `{ kind: "cardCost" | "attackDamage" | "hpCost" | "block" | ... , op, value }`，
  由框架包成 `layer:"enhancement"` 的修饰符注入管线——**强化数值不得直接改写 effect.value**，
  否则 `DamageDealt.layers` 无法追溯（ADR-003）。

## 4. 构建期校验清单（tools/content-validator 实现）

- [ ] 所有 id 全局唯一、命名符合 `snake_case`
- [ ] 引用的 keyword / condition / target / handler 全部已注册
- [ ] `appliesTo` 指向的卡牌存在；`mutex` 互相引用对称
- [ ] i18n key 在 zh-CN 文案表里有对应条目
- [ ] 图标/卡图资源路径存在
- [ ] 数值字段类型与范围合法（cost ≥ 0、split 之和 = 1 等）

## 5. 新增内容流程（团队公约）

```
写/改 JSON → 内容热更即时预览（开发期）→ content-validator 通过 → 提交
```

只有"现有 handler 无法表达的机制"才允许动 `src/core`，且必须补单测。

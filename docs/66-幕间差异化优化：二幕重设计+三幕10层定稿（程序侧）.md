### 实装口径登记（就地，代替原条款）

- **幕规则不进存档**：`rules` 只在 `ActDefinition` → `BattleConfig.actRules` → `BattleState.actRules` → `Draft.actRules` 之间流转，**不写入 `RunState`、不入回放序列化**。理由：规则由幕定义决定，进档等于把静态配置复制一份进存档并加大 migration 面；`SCHEMA_VERSION` 维持 **17** 不变。
- **纯参数解析与副作用分离**：新增 `src/core/combat/act-rules.ts` 只做**参数解析**（`hasActRule` / `actRuleParams` / `forgeHeatFromTurn` / `forgeHeatActive` / `mourningStacks`），**不含任何副作用、不 import resolve**——避免 `resolve → act-rules → resolve` 循环依赖。真正的注入动作留在 `resolve.ts` / `reducer.ts` 各自的派发点。
- **常量与默认值**（`act-rules.ts`）：`MOURNING_STACKS_PER_DEATH = 1`；`FORGE_HEAT_DEFAULT_FROM_TURN = 5`、`FORGE_HEAT_STACKS_PER_TURN = 1`。灼烧起始回合可由 `params.fromTurn` 覆盖（§七.4 的「4/5/6 调节阀」据此实现，改数据不改代码）。
- **溺亡挽歌触发范围**：`killUnit` 内 `if (enemy)` 分支，即**只对敌方单位死亡挂**（玩家单位死亡不挂）；召唤物死亡同样挂（§3.1 数值护栏原文）。派发位置在 `fireRelicHandlers` **之后**，与敌人自身亡语（殉爆/分裂）互不干扰，是额外一层。
- **锻炉高温触发时点**：玩家回合开始、`resolveCurses` **之前**，对玩家与全体存活敌人各 `burn +1`。以 `draft.turn` 判定 `>= fromTurn`（默认 5）。
- **sim 透传**：`tools/headless-sim/src/sim.ts` 的 `BattleRunConfig` 新增 `actRules`，`simulateRun` 在每场战斗按当前 `act.rules` 注入——否则 sim 测不到幕规则。**单幕场景（sim:traits / sim 默认）不带 act2 规则，故特性对照表数字无位移**；`sim:2act` 已接线，但 400 局零位移（见下）。

### ❗ 门禁冲突（必须甲方裁决，程序侧未自行放宽）

docs/66 §3.2 称「树状地图生成器已支持 `kinds` 写 `elite`/`rest`，**零引擎改动**」——**实测不成立**，与 docs/48 两条**已冻结门禁**直接冲突，两次尝试均被 validator 拦下：

| 尝试 | 写法 | validator 报错 |
|---|---|---|
| 一 | `kinds: ["elite"]` | 「分支层类型异常」（validator 要求**分支层必须含 `battle`**）+ 4 项 `map-variance` 全挂（§3.3 修订 4：精英层位 ≥5 种取值 / 路径数 ≥4 种 / 节点数 ≥3 种） |
| 二 | `kinds: ["elite"], width: 1` | 「中段层必须声明 width 2~4」（docs/48 §3.1 修订 1）+ `map-variance` 全挂 |

**冲突本质**：§3.2 的「固定骨架」要求 l3/l4/l6 变成**确定性单类型层**；docs/48 要**中段层 width 2~4、分支层含 elite 必含 battle、同层同类 ≤1、精英层位 ≥5 种不聚类**。二者数学上不可同时满足。

### ✅ 已解（2026-10-08 接手方）：门禁兼容的「骨架层 `pin`」

**解法不是放宽 docs/48，而是新增一个「占位」标注**——pin 层只保证**必现**一个指定稀有节点，不动宽度、不动整层类型、不越任何配额：

| 层 | 数据 | 效果 |
|---|---|---|
| l3 | `"pin": "elite"` | 第一个压力峰位置固定可读 |
| l4 | `"pin": "rest"` | 喘息点固定在精英后——「活下来就能喘」 |
| l6 | `"pin": "elite"` | 第二个压力峰 |

- 数据侧：`MapLayerSpec.pin?: "elite" | "rest"`（`src/core/registry/content.ts`）。
- 生成侧（`src/core/map/index.ts`）：pin 层先从随机稀有节点池里**占位**，其余名额照旧随机 → 宽度仍由种子掷 2~4、kinds 仍混合、**全图精英 2~4 / 篝火 1~3 / 同层同类 ≤1 / 精英层位 ≥5 种**四条门禁全部原样成立。兜底图 `fallbackMap` 同样兑现 pin。
- 校验侧：validator 注册 `pin` + 两条新检查（只能标中段层；`pin:"elite"` 必须自带非空 elitePool）。
- 实测（400 种子）：三层 pin 命中 **400/400**；精英层位签名 **7 种**（门禁 ≥5）；精英总数分布 2/3/4、篝火总数分布 1/2/3，同层同类 ≤1 恒成立。单测锁死在 `tests/unit/map.spec.ts`。

**三条必须让甲方知道的语义边界**（不是 bug，是「不动门禁」的数学后果）：

1. **「必现」≠「必经」**：pin 层仍是 2~4 个节点，玩家**可能从旁边的普通节点绕过**精英。真·必经（单节点层）需要放宽 docs/48 宽度门禁。
2. **l6 是「必现一个精英」，不是 §3.2 写的「双精英并列」**：`analyzeMapGraph` 有冻结规则「同层精英 ≤1」，双精英需要单独豁免。
3. **副作用**：为不跌破「精英层位 ≥5 种」，pin=rest 的 l4 **允许**随机精英落进来（400 种子里 133 次）——l4 有时是「篝火 + 精英并存」层；喘息点一定在，但那层可能同时摆着一场精英战。

**若甲方要更强的骨架（真·必经 / 双精英同层）**：请明示放宽哪一条（宽度 / 同层精英 ≤1 / 精英层位方差），程序侧再改；否则当前形态就是「门禁不动」下的上限。

## §零 一句话方案

**一幕教你规则，二幕改变规则，三幕验收规则。**第二幕的平庸不是怪设计得差，是「节奏型、遭遇编排、战斗规则」三样都和一幕同构——本文给二幕装「幕规则 + 组合题遭遇 + 固定压力骨架」，给三幕定 10 层高压决赛圈，让三幕各自「每回合算的东西」都不一样。

## §三 第二幕优化方案（保留全部资产，动三样）

### 3.1 幕规则「溺亡挽歌」（ActRule 新机制，小成本）

> **规则**：第二幕的战斗中，每当一名敌人死亡，玩家获得 1 层蚀锈。
> **风味**：圣堂不许死者安息——每一个倒下的圣堂居民，都把锈水溅到你身上。

- **它改变什么**：斩杀从「收益」变成「收益 + 代价」——AoE 一波全灭 = 当场吃 N 层蚀锈（DoT 叠在自己身上），于是「先杀谁、什么时候全灭、要不要留一只残血缓口气」成为每场战斗的真实决策。与二幕的蚀锈主题（锈疱鼓腹兽 / 深潜者 / 唱诗长）同频共振。
- **实现**：`ActDefinition.rules?: readonly ActRule[]`（新字段）+ `killUnit` 敌人死亡点按幕注入一次 `applyBuff(corroding, 1)`。一处钩子 + 一个字段，validator 注册。**不与怪物自身亡语冲突**（殉爆/分裂照跑，幕规则是额外一层）。
- **数值护栏**：召唤物死亡也挂（虫群流不再是无脑白给）；`phaseGuard`/不屈等防御机制不受影响。哨兵重点盯 AoE 卡组（docs/64 死亡面具同向叠加，收割流可能反而更强——方向预期内，幅度真人实测）。

### 3.2 节奏型：恢复「高压 - 喘息 - 更高压」固定骨架

> **【程序侧 2026-10-08 实装注 · 已落地】** 下方「零引擎改动」的判断经实测**不成立**，已改用门禁兼容的「骨架层 `pin`」实装：l3 = 必现精英 / l4 = 必现篝火 / l6 = 必现精英，**docs/48 任何一条门禁都没动**。⚠️ 语义边界：pin 给的是「必现可读」不是「必经不可绕」；且 l6 是**单个**精英，不是下方写的「双精英并列」（`analyzeMapGraph` 的「同层精英 ≤1」是冻结规则）。详见开头「实装状态 → ❗门禁冲突 → 已解」。下方原文留档。

把 docs/40 §三 的原设计**按 10 层骨架复活**（树状地图生成器已支持 `kinds` 写 `elite`/`rest`——`kinds:["elite"]` 即必经精英层，零引擎改动）：

| 层 | 现状 | 改为 | 效果 |
|---|---|---|---|
| l3 | 混合随机 | **w1 必经 elite**（精英池 3 只抽 1） | 第一个压力峰，位置固定可读 |
| l4 | 混合随机 | **w1 必经 rest** | 喘息点固定在精英后——「活下来就能喘」 |
| l6 | 混合随机 | **w2 双 elite 并列**（池抽不重复） | 第二个更高压力峰，二选一给选择权 |

一幕保持「生成器随机」的轻松节奏——**两幕的节奏型从这一刻起不同**：一幕是散步，二幕是「爬山-平台-再爬山」。

### 4.2 幕规则「锻炉高温」

> **规则**：第三幕的战斗中，**第 5 回合起，双方在各自回合开始获得 1 层灼烧**（每层每回合 −1 生命上限，战斗内，上限沿用 5 层）。
> **风味**：靠炉心越近，连空气都是烫的——在这里，时间是双方的敌人。

- **它改变什么**：软计时器。无限龟缩/磨血流在三幕被判死刑——你的 Build 必须有合格的 DPs 才配进决赛；同时敌人也在烧，「让怪先烧死」是防御流的合法反用（白热锻渣自燃的放大版）。
- 实现：与溺亡挽歌共用 `ActDefinition.rules` 机制（钩子：回合开始按 `turn >= 5` 对全场 applyBuff burn 1）。小成本。
- 哨兵重点：防御流（铁皮王八/镜面装甲/夜春蛋苯）在三幕的存活率——「拖」被规则针对，但这些 Build 的 DP 恰好也靠拖结算，需要真人实测定灼烧起始回合（4/5/6 是调节阀）。

### 4.3 幕 Boss「炉前督军」（占位骨架，详案随批 2 填）

- 定位：**幕 Boss，不是终局 Boss**——终局在第三幕之后（§五）。
- 骨架：**280 HP 双阶段**（docs/65 锈心的压缩版）：一阶段「锻压」（物理 + 蓄 2 链释放 24 + 固定力量 2）、二阶段「溢锈」（<50%：污染 + 蚀锈 + 召唤虫群 + 魔免节拍窗）。
- docs/20 锚点：单发 ≤24，全员读招，免疫断链 + 眩晕抗性。

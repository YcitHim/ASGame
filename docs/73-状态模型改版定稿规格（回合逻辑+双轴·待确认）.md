## §一 回合逻辑（先把你说的那句「搞清楚」定死）

### 1.1 名词定义

**一个单位的一个「回合」= 它的行动阶段 + 它的结束阶段。**

| 阶段 | 玩家侧 | 敌方侧 |
|---|---|---|
| 开始 | 抽牌、结算回合开始类效果（灼烧扣上限、坚韧加格挡、充能、低血段…） | 意图已在上回合预告 |
| 行动 | 出牌 / 结束回合成按钮 | 执行意图 |
| **结束** | 手牌弃置、格挡清零、**自己身上的「剩余回合」−1** | **自己身上的「剩余回合」−1** |

一局的顺序：`战斗开始 → 玩家回合1 → 敌方回合1 → 玩家回合2 → 敌方回合2 → …`

### 1.2 核心规则（建议锁死为铁律）

> **「剩余回合」只在承载者自己的回合结束时 −1。**

为什么必须是这条（这是已经踩过的坑）：
- 如果改成**玩家回合开始**统一 −1：敌人在**它的**回合末给你挂 1 回合冰缓，下一次玩家回合一开始就扣成 0 —— 玩家**从头到尾没见过这条诅咒**（状态栏看不到、费用没变化）。这就是甲方 2026-10-07 实报的「颠倒对角色不生效」，已修并锁了回归用例 `tests/unit/p28-reverse-curse.spec.ts`。
- 按「承载者自己回合结束 −1」，**「1 回合」= 承载者至少完整经历一次自己的回合**，永远看得见。

### 1.3 ✅ 已确认（甲方 2026-10-09 二次确认）：「至少要在承载者回合开始时吃到效果」

甲方原话：「对方给我们上了诅咒，**起码要在我们玩家回合开始时吃到效果**，就算一回合。比如敌人给我上了 1 回合冰缓，那我回合开始时就会吃到冰缓。」

**这就是下面的 A，而且当前实现已经就是这样**——不需要改：

```
敌方回合 T ：意图执行 → 给玩家挂「冰缓 1 回合」
             ↓ 敌方回合结束（只递减**敌人自己**身上状态的剩余回合，玩家身上的不动）
玩家回合 T+1：回合开始 —— ★ 冰缓在此刻生效（手牌费用 +1）★
             行动……
             回合结束 → 玩家自己身上的「剩余回合 −1」→ 冰缓 1→0，移除
```

对称地，玩家给敌人挂的诅咒，在**敌人自己的回合开始**生效、在**敌人回合结束**递减。两边的判定点都在 `decayTimedCurses`（`core/combat/resolve.ts`），调用点两处：玩家 EndTurn、敌方回合结束。

**锁这条的回归用例**：`tests/unit/p28-reverse-curse.spec.ts`（4 条，其中第 1 条就是「敌人挂的 1 层颠倒必须活过玩家一整个回合：状态栏能看到、手牌费用全在 0~3、本回合结束才归零移除」）。当年把判定点写成「玩家回合开始」时，这 4 条全红——那正是你报的「颠倒对角色不生效」。

**唯一要补的边界情况**：如果某个状态是在**承载者自己的回合内**被挂上的（例：敌人亡语在你的回合里给你挂 1 回合诅咒），按现在的实现它会在**同一个回合的结束**就到期 → 你依然一次都没吃到。今天没有这样的来源（敌人的诅咒全部走在敌方回合的意图里），但新模型下会出现「开场随机诅咒」「道具/事件在战斗内挂状态」这类入口，所以我打算加一条**新鲜度护栏**：

> 在本单位**当前回合**内新挂上的状态，本回合结束时**不递减**（顺延到下一个自己的回合结束才 −1）。
>
> 效果：任何状态都至少完整活过一次承载者的回合开始——这正是你要的那句话的严格实现。

这条护栏要不要加，你点个头（我倾向加：它把「起码吃到一次」从**约定**变成**引擎保证**）。

## §三 需要你拍的 6 处（这几处猜错就是返工）

**① 虚弱 / 胆怯的单层数值（最重要）**
现在是「每层 −10%（虚弱）/ +10%（胆怯），最多 5 层」→ 上限 −50% / +50%。

**③ 荆棘 / 坚韧的基础时长**

## §四 这不是「改数值」，是一次模型变更（要知道在推翻什么）

**docs/46 §二 当年把三套机制合并成「层级型」**（虚弱层级化、易伤→胆怯、反伤→荆棘），理由写得很明确：「新概念是旧概念的严格泛化就合并，不留两套近似机制」。本次改版会把**虚弱 / 胆怯 / 荆棘 / 坚韧**从「层级型（不衰减）」改回「带剩余回合」，即：
- **推翻 docs/46 §2.1 / §2.2 / §2.3 的合并口径**；
- **推翻 docs/49 §7.3 观察清单第 2 条**（淬锈多段叠层）与**第 8/9 条**（铁皮王八荆棘刷新的整套讨论）——它们都建立在「荆棘 = 层数、不衰减、回合末覆盖刷新」之上。

我不是说不能改（你有权改），而是提醒：这几条当时的裁决理由会一起失效，需要你在文档里回写一句新裁决，否则以后翻旧账会打架。

回合口径（已写成引擎保证，不再是约定）：

> **剩余回合只在「承载者自己的回合结束」递减。**
> 敌人趁我方回合间隙给你挂的 1 回合诅咒，必定在你**下一个回合开始时**生效并吃满你的一整个回合。

补充一条实现细节（**这条是 §一.3 的兜底，实装时做成了引擎护栏**）：

> **新鲜度护栏**：某状态若是在承载者**本回合**刚挂上的，则跳过承载者这一次的回合结束递减。
> 因此「任何状态至少完整活过一次承载者的回合开始」不是各调用点的约定，而是引擎强制。
> 实现上用「回合实例」编号（玩家侧 = `turn×2`、敌方侧 = `turn×2+1`），
> 精确区分「玩家回合里挂给敌人的诅咒」和「敌人自己回合挂的」，避免敌人白吃一个回合。

### 7.3 需要你回写的三处（都是实装后才显形的）

**① 新鲜度护栏的副作用：「自己给自己挂」会多活一回合。**
例：你在自己回合用「自冰缓」挂 2 回合冰缓，实际会持续到你第 3 个回合结束（护栏把本回合那次递减挡掉了）。
- 想要的玩家体感：「2 回合」= 从挂上那一刻起算满 2 个自己的回合。
- 现状：「2 回合」= 2 + 1（护栏赠送）。
- 三个选项：**(a)** 保留现状（「任何状态至少吃满一个完整回合」优先）；**(b)** 护栏只管「别人挂的」（实现上做不到干净区分，除非把护栏拆掉）；**(c)** **拆掉护栏**——你原始诉求（敌人挂的诅咒至少吃一次）靠「承载者自己回合结束递减」已经天然满足，护栏只是额外保险。
- **我的建议：拆掉 (c)**——护栏带来的「+1 回合」比它防的边角情况更常见，且原始 bug 不依赖它。**等你一句话。**

**② 灼烧留下的「生命上限伤疤」要不要在灼烧到期时还回去？**
现状：灼烧每回合扣上限，**灼烧到期后已扣掉的上限不归还**，要到战斗结束才恢复（当前实现，与旧版一致）。
你的「持续 2 回合」如果指的是「2 回合内越烧越痛、烧完就没事」，那就该在到期时把上限还回去——这是一行改动，但会明显改变灼烧的强度定位。**等你一句话。**

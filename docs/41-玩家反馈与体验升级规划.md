## §二 v1.0.1 热修包——错误信息清零

**版本主题**：先把说错的话改对。全部为小改动，随改随上。

### 2.1 能量提示残留（反馈 4/6）

| 项 | 规格 |
|---|---|
| 病灶 | 打出失败（能量不足/目标非法）的提示 toast 生命周期与回合无关，回合切换不清理 |
| 修法 | toast 携带 `turnId`，`TurnStarted` 事件到达时清理所有非本回合 toast；同时该类提示存续上限 2.5 秒自动消散 |
| 验收 | 复现路径固化进 golden replay：空能量点牌 → 提示出现 → 结束回合 → 新回合提示必须已消失 |

### 2.2 意图标签与实际行为对齐（反馈 10）

| 项 | 规格 |
|---|---|
| 修法 | `IntentIcon` 的 `debuff` 分支不再硬编码「诅咒」，改为读取意图 payload 的实际减益名（易伤/虚弱/诅咒/蚀锈…）；payload 未带具体名时兜底显示「干扰」而非「诅咒」 |
| 数据侧 | 敌人 AI 发 `IntentDeclared` 时 `debuff` 类意图必须附带减益 id——补全所有敌人数据，缺漏者 validator 报错（走 docs/04 数据规范） |
| 验收 | 锈喉全技能树的意图显示与其实际行为逐条对账，golden replay 截图存档 |

### 2.3 「保留」词条消歧（反馈 5）

| 项 | 规格 |
|---|---|
| 词条改文 | 保留：**手牌**——「回合结束时，此牌不因弃牌阶段被弃置。」 |
| 护盾存续另立词条 | 若存在「护盾不清零」类效果（格挡保留），禁用「保留」字样，改立词条 **「维续」**：「格挡在回合结束时不清除。」两个词永不混用 |
| 排查 | 全卡池/遗物/强化检索「保留」二字，凡指护盾者一律改「维续」，i18n 同步 |

### 2.4 机制词条补全（反馈 1/3 的文字部分先行）

新增 glossary 条目，牌面关键词悬停即可见：

| 词条 | 文案 |
|---|---|
| 弃牌阶段 | 「每个你的回合结束时，未打出的手牌进入弃牌堆。牌堆抽空后，弃牌堆洗回牌堆。」 |
| 血契（bloodpact） | 「以自身生命为代价催动卡牌。失去的生命是**成本**，造成的回血/伤害是**效果**——血械侍僧的交易从来都是先付款后交货。」 |
| 维续 | 见 2.3 |

> 注：卖血回血的**呈现层**优化（净收益预览）随 §四教学包一起做，文案词条先顶上。

**v1.0.1 出口门禁**：上述 4 项全部进 golden replay 回归；真人开 1 局按反馈路径逐条复现确认。无 sim 数值门禁（无数值改动）。

## §三 v1.0.2 战斗表现包——让挨揍看得见

**版本主题**：玩家被打这件事，目前是「屏幕抖一下 + 数字变了」。这是动作游戏级别的信息缺失，必须补齐。

### 3.1 敌人攻击动作（反馈 2/8）

| 项 | 规格 |
|---|---|
| 前扑动作 | 敌人攻击时向玩家方向位移 12~16px 后归位，时长 0.25s，ease-out；多段攻击（hits>1）按段数重复，段间隔 0.12s |
| 非攻击意图 | defend 上护盾时敌人身上起护盾微光；charge 蓄力时敌人本体出现逐渐收紧的呼吸缩放（与 §三.3 的预警文案形成视听双通道） |
| 接入点 | 走既有 anim-queue（`src/ui/anim-queue`），敌人攻击事件入队即播，**不动核心层时序**——表现层订阅事件，与结算解耦 |
| 降级 | 设置页「屏幕震动」开关扩展为「战斗动画」三档：完整 / 简化（仅飘字）/ 关闭 |

### 3.2 受击飘字（反馈 8）

| 项 | 规格 |
|---|---|
| 玩家受击 | HP 条上方飘出红色 `-N`；被格挡部分单独显示蓝色 `挡N`；完全格挡显示 `格挡！` |
| 玩家受减益 | 对应减益图标 + 名称短暂浮现在玩家状态栏位置 |
| 敌人受击 | 现状补齐对账：敌人侧飘字已存在则统一字号/动效规范，不一致处对齐 |
| 规则 | 飘字是**结算结果的可视化**，只读事件流，不回写状态 |

### 3.3 蓄力预警三段式（反馈 11）——本包最重要的信息设计

现状：「2回合 → 下回合 → 消失 → 挨打」。改为**状态机式文案**，玩家任意时刻看一眼都知道自己处于哪个阶段：

| 阶段 | 条件 | 意图副标文案 | 视觉 |
|---|---|---|---|
| 蓄力中 | thenIn ≥ 2 | 「蓄力 · N回合后释放 X」 | 常规金框 |
| 临近 | thenIn = 1 | 「下回合释放 X · 准备防御」 | 红框（既有 imminent 样式） |
| **即将承受（新增）** | 本回合敌人行动阶段将释放 | **「即将承受 X 伤害」** | 红框 + 边框脉冲，数值直接写进文案 |

关键点：**「即将承受」挂在敌人行动阶段**，替代过去的「预警消失」——预警不再消失，而是变成结算预告。玩家看到的链路变为：红屏预警 → 「即将承受 24」→ 前扑动画 → 飘字 -24。因果闭合。

Boss 阶段递增蓄力（docs/18 拍板路线）同样适用：阶段文案显示当前阶段实际值，不显示「???」。

**v1.0.2 出口门禁**：三职业各真人实测 3 局，重点验证「即将承受」是否能被首次见面的玩家正确理解（找 1 名未接触过本作的测试者，观察其是否在临近回合主动防御）；动画三档开关生效。

## §四 v1.0.3 教学与说明包——首局体验

**版本主题**：不拦人的教学。本作是单机肉鸽卡牌，教学必须可跳过、可回看、绝不弹窗打断战斗。

### 4.1 首遇提示（toast-once 系统）

| 项 | 规格 |
|---|---|
| 机制 | 每类机制首次在游戏中出现时，屏幕下方浮出一条 2~4 行的说明条，含「不再提示」按钮；触发记录入 meta 存档，跨局不再出现；图鉴页可回看全部提示 |
| 首批触发点 | ① 首次回合结束有手牌未打出 → 弃牌阶段说明；② 首次打出血契牌 → 卖血=成本说明（含**净收益预览**：牌面追加一行小字「净 +4 HP」，见 4.2）；③ 首次获得保留牌；④ 首次见敌人蓄力；⑤ 首次能量不足 |
| 原则 | 同屏至多 1 条；战斗高潮（Boss 释放回合）延迟到行动结束后出现 |

### 4.2 卖血牌呈现优化（反馈 1 的根治）

| 项 | 规格 |
|---|---|
| 牌面净值行 | 凡「失去 X HP + 回复 Y HP」同牌并存（如 `transfusion`：血契 2 / 回 6），牌面效果文本下追加灰色小字 **「净 +4 HP」**；升级后自动重算 |
| 结算飘字合并 | 此类牌的自伤与回血两跳飘字合并显示为一次净值变化，避免玩家看到「-2 然后 +6」以为出了 bug |
| 不改机制 | 血契作为成本的设计本身保留——它是血械侍僧的职业身份（侍僧卖血，docs/38 B-1 对偶句），改的是**叙事顺序**不是数值 |

### 4.3 新手教程（反馈 7）——教学遭遇战

| 项 | 规格 |
|---|---|
| 形态 | 首次进入远征前，弹一次可选「要人带路吗？」；选是则进入**教学遭遇战**：固定种子的 3 场连续战斗（小怪 → 蓄力精英 → 模拟 Boss），每场聚焦一个主题：出牌与能量 / 读意图与防御 / 蓄力与爆发 |
| 引导方式 | 场上高亮 + 一句话提示（「这张牌需要 1 点能量，点它打出」），玩家操作正确才推进；**随时可点右上角跳过** |
| 奖励 | 完成教学无额外奖励（避免老玩家被迫打），只在图鉴解锁「引路人」徽章 |
| 复看 | 设置页可随时重进教学 |
| 规模控制 | 教学只做固定脚本 3 场，**不做全系统覆盖**——词条靠 4.1，进阶靠玩家社区，教学只管「第一局不迷茫」 |

**v1.0.3 出口门禁**：3 名未接触过本作的测试者裸装首局，要求：① 无人问出反馈 1/3/5 的同类问题；② 教学遭遇战完成率 ≥ 2/3（允许主动跳过）；③ 教学后首局存活至第 3 层以上 ≥ 2/3。

## §五 T1 随身遗物强度收敛（反馈 9）

**问题**：8 件 T1 随身遗物（docs/38 A-1）强度方差过大，最优件与最弱件差距被玩家一局就能感知，开局抉择退化为「roll 血泵」。

**收敛原则**（与 docs/19 数值冻结协议兼容，本次属体验线特例授权）：

1. **先抬后压**：优先 buff 垫底件，nerf 只动明显超线件——开局拿到的第一件遗物不该让人想 rematch。
2. **目标区间**：最弱件期望强度 ≥ 池子中位数的 70%（以 sim 首幕通关率代理）。
3. **身份件不动**：职业固定身份件（破碎圣油瓶/凹痕线圈/锈念珠）不参与本次收敛，它们是职业地基。
4. **流程照铁律**：数值改动一律 sim 复跑（30%~70% 健康，期望 45%~60%）+ golden replay 随改随录 + 真人实测拍板，模拟器只作兜底（docs 长期约定）。

**执行**：sim 先出 8 件 T1 各自的首幕通关率分布 → 我据此出逐件裁决表（单独成档，编号顺排）→ 程序实施 → 复跑验收。

## §七 明确不做的事

1. **不改血契机制本身**——卖血是职业身份，只改呈现与说明（§四.2）。
2. **不做强制不可跳过的教学**——任何弹窗式、锁定操作的引导都不做，教学全程可跳过。
3. **不做全系统教学覆盖**——教学遭遇战只管 3 个主题，其余靠词条与首遇提示。
4. **不动核心层结算时序**——动画与飘字全部走事件订阅，anim-queue 只做可视化，不引入「动画驱动结算」的新耦合。
5. **不在本线调整 T2/T3 遗物**——反馈只指向 T1 开局池，T2/T3 等 v1.1 实测数据再说。
6. **「保留」不改名为生造词**——牌保留沿用「保留」，护盾存续新立「维续」，两词分工（§2.3），不做全局换皮。

## 程序执行记录 · v1.0.1 热修包（2026-10-07）

- **§2.1 能量提示残留**：`battleStore` 的提示加回合戳 `messageTurn`；`dispatch` 里 `TurnStarted.turn > messageTurn` 即清空；error 类提示 2.5 秒自动消散（`MESSAGE_TTL_MS`），"选择目标"这类操作引导（`messageKind: "info"`）不自动消散。UI 侧报错血色 / 引导金色区分。
- **§2.2 意图标签**：`IntentIcon` 的 debuff 分支不再硬编码"诅咒"，改读 `payload.buffId` → `buffMeta` 实际减益名 + 层数（污染的 unit 是"点"，显示"污染 22点"）；缺 `buffId` 兜底"干扰"。数据自查：6 只带 debuff 意图的敌人**本来就都有 buffId**（锈喉是污染，所以旧版显示"诅咒"确实在骗玩家）；validator 新增规则，debuff 意图缺 buffId 报错（含 thenIntent 链递归）。
- **§2.3 保留消歧**：`保留` 改文为"回合结束时，此牌不因弃牌阶段被弃置。保留的是手牌，不是格挡。"；新立 `维续`「格挡在回合结束时不清除。」。**全池检索结论：当前卡池只有 `brace` 用了"保留"，且是手牌保留（retain 关键词），语义正确；无任何护盾存续类效果，`维续` 为预留词条（等第一个护盾留存机制落地即可直接用）。**
- **§2.4 词条补全**：新增 `弃牌阶段`、`维续`；`血契` 改为策划文案（成本 / 效果的对偶句）。词条总数 14 → 16。
- **验收方式偏差登记（重要）**：策划要求"复现路径固化进 golden replay"。**golden replay 只覆盖 core 的「输入流 → 事件流」，而 toast / 意图标签 / 词条全是 UI 纯表现，不进事件流**，无法用 golden 表达。改为等价且更强的回归位：`tests/unit/toast-lifecycle.spec.ts`（空能量点牌 → 提示出现 → 结束回合 → 提示清空；+ 2.5 秒自动消散）、`tests/unit/intent-icon.spec.ts`（污染/虚弱/蚀锈/兜底四例）、`tests/unit/glossary.spec.ts`（保留不指格挡 / 维续不含保留 / 弃牌阶段与血契）、`tests/unit/content-validator.spec.ts`（debuff 缺 buffId 报错）。golden 7 盘哈希逐条未变（本包无 core 改动）。

## 程序执行记录 · v1.0.3 补丁（2026-10-07 玩家实测三连）

玩家实测发现三处，全部修复并复验：

## 程序执行记录 · 调血改版 + 教学入口 UI（2026-10-07，按甲方口头指令）

### 一、调血（transfusion）：先扣 5 血，下回合返回 7 血

| 项 | 改前 | 改后 |
|---|---|---|
| 血契代价 | 2 | **5** |
| 效果 | 立刻回复 6 HP | **下回合开始时回复 7 HP** |
| 升级 | 回 9 | 回 10（升级幅度沿用 +3 的老口径，你可改） |
| 牌面净值行 | 净 +4 HP | **净 +2 HP（下回合）** |

- **实现**：新增 buff「回血印记」（`mending`）+ `resolveMending`——玩家回合开始时按印记层数回一次血，随后印记消失。与蚀锈同构：特殊 buff 走专门结算，不进泛用 tick（否则 `duration` 会在结算前先被扣掉而白掉）。
- **为什么牌面要写「（下回合）」**：docs/41 §4.2 的净值行口径没变，但延迟到账必须写出来，否则玩家会以为打完立刻回血——这正是反馈 1 那类误解的翻版。
- **词条与图标**：新增词条「回血印记」（先付代价、下回合才到账的回血）+ 状态图标（愈）。
- **教学同步**：血械机制课的旁白改成「先付 5 血，下回合开始回 7 血」；顺带修正一处**卡名错**——原文写的是「输血」，那是另一张牌（`bloodletting`），已改回「调血」。教学每场开打前把 HP 垫到 ≥25，保证付得起 5 血的血契（否则机制课可能没血可付 → 卡死）。

**数值影响（需要你登记在案）**
- 300 局 bloodwright AI 复跑：**44.3%**（改动前 400 局口径 42.0%，差异在噪声范围内），但**基线要按新口径重记**。
- 血泵（每次卖血回 2）的触发次数会随血契卡使用率一起变化——`docs/program/1.0.x-T1随身遗物强度分布报告（程序侧）.md` 里的数字建议在裁决前重测一次。

### 三、顺带修掉的一个真 bug

教学步骤的 `grant`（把样例牌塞进手里）原来挂在 `immediate` 的 watcher 上，而 **watcher 跑在 `onMounted` 之前——那时战斗还没建好**，`give card` 会打空。正常流程看不出来（换课时不重新挂载），但**从设置页回到战斗、或中途刷新再进来**，机制课要用的那张牌就会缺失，严判定可能直接卡死。已改成「战斗建好之后再发」。

- 校验：单测 **406 例 / 62 文件**全绿；validator 通过；golden 7 盘哈希未变。
**补（同日，甲方反馈）**：调血牌面**不再标净值行**（「净 +2 HP（下回合）」太难看了）。
顺带把 §4.2 的适用范围收窄成一句话：**净值行只给「同一次出牌里先扣血、又立刻回血」的牌**——只有那种牌会冒出「-2 然后 +6」两跳飘字、让玩家以为出了 bug。延迟到账的回血和代价本来就隔一个回合，不存在两跳打架，再标一行小字只是给卡面添噪音。
（数据里现在没有这类牌了，所以净值行暂时不出现在任何卡面上；机制留在 `ui/card-value.ts`，将来的「卖 2 回 6」类牌仍然会显示。）
另外两处引用净值行的文案也一并改掉：教学血械机制课的旁白（改为「这笔账要等一个回合，别急着算」）、首遇提示的血契条目（改为「先付款，后交货」，不再提「牌面下方」）。

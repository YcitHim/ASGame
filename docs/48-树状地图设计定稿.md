## §一 现状诊断：假分支

| 现状（`act1.json` + `core/map/index.ts`） | 问题 |
|---|---|
| 8 层，每层 width 1~3 个候选，`chooseNode` 只在**本层内**选一个 | 层与层之间**零耦合**：这层选什么不影响下层给什么 |
| 候选按层独立生成 | 没有「路径」这个概念，只有「每层抽一次签」 |
| 玩家看不到全局 | 无法规划，「精英→篝火→Boss」的节奏是撞上的，不是走出来的 |

一句话：现在的地图提供的是「每层的偏好选择」，不是「整幕的路线选择」。玩家的长期决策（我这局要贪还是要稳）没有落点。

## §二 设计目标：真分支的三个支柱

1. **连通性**——选择有后果：选了左边的精英，就放弃了右边的篝火，而且这个放弃是**看得见、追不回的**。
2. **可见性**——规划成为可能：进幕即见全图，从起点到 Boss 的每条路都能提前推演。
3. **不对称性**——分支有性格：左支「两精英一篝火」、右支「三小怪两事件」，路线选择 = 风险偏好声明。

## §三 结构规格（DAG）

### 3.0 深度修订：8 → 10 层（修订 1）

甲方质询「8 层会不会太短」——**成立**。树状地图的核心价值是规划视距，而 8 层结构里中段只有 5 层，扣掉篝火/事件，真正的路线抉择只有 3~4 次，视距刚展开就收束。

| 维度 | 8 层（原案） | 10 层（修订） |
|---|---|---|
| 决策层数 | 中段 5 层，路线抉择 3~4 次 | 中段 7 层，路线抉择 5~6 次 |
| 构筑弧线 | 走完一幕牌组/遗物刚起步，Build 没成熟就见 Boss | 多 1~2 场战斗 + 更从容的篝火窗口，构筑有成熟感 |
| 走廊可读性 | 层数太少，「贪/稳」两条路挤在一起分不出性格 | 7 个中段层足以让两条走廊分叉再汇合 |
| 成本 | —— | 单幕时长上浮约 20%；**sim 基线反正因地图全量重录，幕长改动搭同一班车，边际成本最低的窗口就是现在** |

结论：**两幕统一 10 层**。12 层以上否掉——act1 敌人池撑不起那么高的复用率（同层战斗会反复撞同样的怪），双幕总时长也会突破舒适区。

### 3.1 骨架参数

| 项 | 规格 |
|---|---|
| 深度 | **10 层**（修订 1）：l0 起点 / l1~l7 中段 / l8 祭坛 / l9 Boss，act1/act2 同规格 |
| 每层节点数 | l0（起点）= 1；l8（祭坛）= 1；l9（Boss）= 1；**中间 l1~l7 每层 2~4 个** |
| 全图节点数 | 17~31 个/幕（典型 ~21） |
| 列坐标 | 节点在层内占列（0~3），UI 按列排布 |
| 边 | 只连**相邻两层**；两端列差 ≤1（**出边上界因此天然为 3——三分叉是结构的自然产物**，回应「三分叉」质询）；**边不相交**（平面约束，UI 清爽也让「分支」一眼可读）。**例外**：单节点层（起点/祭坛/Boss）与相邻层之间的边不受列差约束，全连 |
| 连通性 | 除起点外每节点 ≥1 入边；除 Boss 外每节点 ≥1 出边（生成后校验，不合格重新掷） |
| 决策点密度（修订 2） | 每图 **≥2 个三分叉**（3 出边节点）、**≥2 个汇合点**（≥2 入边的中段节点，祭坛/Boss 不计）；start→Boss **可行路径数 ≥8 条**——选择感的量化底线。生成后校验，任一不过整图重掷 |

### 3.2 节点类型分配

- 每层可用类型**沿用现有 `MapLayerSpec.kinds` 与 weights**（不发明新配比），改为在「该层的 2~4 个节点」上分配，约束四条：
  1. 同层**精英 ≤1**、**篝火 ≤1**；
  2. l1 不出精英（开局不堵门）；**l7 不出精英**（祭坛前一层不搞突袭，保安全走廊的可读性）；
  3. l8/l9 维持祭坛 → Boss 的固定收尾（现状如此，保持）；
  4. **全图总量（修订 3 附带）**：精英 2~4 个/幕、篝火 1~3 个/幕——走廊保证（§3.4）的物质基础，没有它走廊校验会频繁重掷。
- 事件节点只显示「？」图标，内容不可见（现状口径保持）——**可见的是类型，不是结果**。
- 精英池抽取逻辑（同幕按层序抽、后排斥前）原样沿用。

### 3.3 生成与复现

- 同种子同图：结构生成走**独立 `map` RNG 流**（docs/38 已有 map 流口径），新增边生成只消耗该流，不污染 combat/curse 流。
- 生成失败（连通性校验不过）就地重掷该层，最多 10 次后整幕重掷——validator 加一条「所有生成种子连通性必过」的常驻检查。
- **整图校验（修订 2/3 附带）**：连通性之外，每图生成后须过——三分叉 ≥2、汇合点 ≥2、可行路径 ≥8 条、安全/贪婪走廊各 ≥1（§3.4）；任一不过整图重掷。
- **跨种子方差断言（修订 4）**：validator 常驻抽样（≥100 种子），断言分支点数、精英层位、可行路径数**不聚类**——「同种子同图」是复现性，「**不同种子不同图**」是内容量，两者都是门禁。一直重复一张地图的感觉，根因不是玩家错觉就是方差失守，这条断言就是用来抓后者的。
- 过幕（docs/40）：转幕后按 act2 规格生成新图，互不影响。

### 3.4 走廊保证与换路机制（修订 3）

甲方质询「是否区分高风险精英路与安全路、能否切换」——答案是：**路线性格靠生成保证，换路靠汇合点保证，而且切换是玩家的基本权利，不需要专门机制**。

**两条走廊（生成后校验，缺一即整图重掷）：**

| 走廊 | 定义 | 服务谁 |
|---|---|---|
| 安全走廊 | 存在 ≥1 条 start→Boss 路径：**精英 ≤1 且篝火 ≥1** | 残血/保守玩家——「想稳永远有路」是结构保证，不是运气 |
| 贪婪走廊 | 存在 ≥1 条 start→Boss 路径：**精英 ≥2** | 满血/进攻玩家——「想贪永远有账算」（精英掉遗物，风险与收益对等是本作既定经济） |

**换路 = 汇合点的使用权**：玩家永远不被首次选择锁死——每一步都在「与当前节点有边相连的下层节点」中任选。从精英路切回安全路（或反向）发生在**汇合点**（≥2 入边的节点）：两条支路在那里交汇，你从哪条来都能走上另一条的去程。每图 ≥2 个汇合点（§3.1），保证「开局贪精英 → 挨了狠的 → 中途切去篝火」这条经典弧线可操作。**这正是假分支给不了、三分叉+汇合点才能给的体验**：选择有后果，但后果可以被后续选择管理。

**UI 不标注走廊**——图上不写「安全路」三个字。精英/篝火图标自己说话，读图是玩家技能的一部分（§二.3：路线选择 = 风险偏好声明，要的就是玩家自己读懂）。

## §四 可见性与 UI

| 项 | 规格 |
|---|---|
| 全图 | **进幕即全图可见**（StS 模式）。10 层也没有藏图的必要——规划本身就是玩法，藏起来等于没收玩法 |
| 状态 | 当前位置（描金）/ 可达节点（亮起可点）/ 已走路径（描边）/ 未达区域（正常显示，不置灰——全图可见的意义就是能提前看） |
| 移动 | 只能点「与当前节点有边相连的下层节点」；点击即走，不二次确认（节点内容页才是决策点） |
| 布局 | 竖排 **10 层**、列向展开；**超出视口时纵向滚动、当前位置自动居中**；边用细蚀刻线；act2 走 `--act-*` 青蓝令牌（docs/43 追认 #10） |
| 美术 | 节点图标沿用现有字形（剑/角/火/砧/匣/颅/？），边与选中态是仅有的新增视觉元素 |

## §五 数值影响与门禁（先说丑话）

**树状地图会让通关率上行**：玩家能绕开精英、能规划篝火时机——这是设计意图（选择权本身就是强度），不是事故。但两条纪律：

1. **不预调任何数值补偿**。先让地图自己跑出门禁数据；通关率若涨出 45~65% 健康区间，那时候的补偿对象是**节点配比**（比如精英出现率），不是敌人数值——地图的账地图还。
2. **门禁独立**：单幕+双幕 400 局复跑（同批种子），与线性图基线对比记录波动；sim AI 需要基础的寻路策略（贪心：血量低偏篝火、否则偏精英/事件——**这不是调 AI 强度，是让 AI 像个普通玩家一样认路**，寻路策略作为 sim 配置项声明，不进游戏逻辑）。
3. golden replay：战斗盘 replay 不受地图影响（战斗内部未动）；**run 级回放（若有）与 sim 基线数字作废重录**——这是本次变更的主要工程成本，一次付清。
4. **幕长账（修订 1 附带）**：8 → 10 层使单幕战斗/事件密度上浮约 20%，单幕时长同步上浮。此账与地图变更**同一次付款**（基线本来就全量重录），不另开门禁；act2 敌人池按 10 层规格配置（docs/47 对账时核对复用率——同一场战斗在一幕里撞见两次以上就要警觉）。

## §七 排期裁定：地图先，九相 Phase 1 顺延

| 序 | 事项 | 理由 |
|---|---|---|
| 1 | **树状地图**（本文） | 结构变更：它改变**每一局**的骨架，之后所有 sim 数值基线都要长在它上面。后做 = 九相 Phase 1 的门禁数字落地即过期 |
| 2 | **九相 Phase 1**（docs/46） | 顺延至地图封版后开工，**直接在新地图基线上跑 400 局门禁**——一次测准，不用测两遍 |
| 3 | Phase 2 机制静默预建 | 不受影响，随时可写（三条锁不变） |
| 4 | docs/47 act2 敌人配置表 | 策划照常交付（v1.1-B 前），不受地图排期影响 |

两个系统**不并行施工**：地图动 run 结构、九相动战斗结算，同时开工会把 sim/golden 的波动搅成一锅无法归因——一次一个变量，这是 0.5 以来的老规矩。

v1.1「沉没圣堂」的最终形态因此明确为：**树状双幕 + 九相（P1+P2）+ act2 敌人/Boss + 音频层**。

## §八 不做的事

1. 不做迷雾/战争迷雾——全图可见是本设计的支柱，不是阉割项。
2. 不做层内回头、不做横向移动——只向前，肉鸽的悔棋不存在。
3. 不新增节点类型（商店等）——本作无金币，现有七类够用。
4. 不做多入口/多结局分岔——起点唯一、Boss 唯一，分岔只在途中。
5. 不在本次调整节点配比与敌人数值——地图的账先记账，超线再还（§五.1）。
6. **不做路线锁死、不做选路后不可换**——换路是基本权利（§3.4），不需要任何专门 UI；走廊是生成的结构属性，不是标注出来的旅游推荐。
7. **不做 12 层以上**（修订 1 附带）——幕长的甜点位是 10 层，再长敌人池和总时长都撑不住（§3.0）。

## 程序执行记录 · 树状地图实装（修订单 · 10 层真树状）

> 依 §七 排序「地图先」。本批实装的是 **修订后** 的规格（修订 1~4）：10 层 / 决策点密度 / 走廊保证 / 跨种子方差。九相 Phase 1 未动。

### 1. 结构（§3.0 / §3.1）

| 项 | 实现 |
|---|---|
| 节点表 | `generateMapGraph(act, seed)` → `{ layers, edges }`；`MapNode` 新增 `col`（层内列 0~3） |
| 深度 | **10 层**：l0 起点 / l1~l7 中段（每层 2~4）/ l8 祭坛 / l9 Boss；act1/act2 同规格 |
| 宽度 | 生成器按种子掷：2（30%）/ 3（45%）/ 4（25%）；实测 19~30 节点/幕，均值 24.9（§3.1 说 17~31） |
| 列 | 从 0~3 里**无放回**取 w 个（可有空隙），保证列差约束下仍有解 |
| 边 | 先保「每个目标有入边、每个源有出边」（取最近列），再随机补到一半——**三分叉与汇合点由此自然产生**；只连相邻层；**两端列差 ≤1；单节点层（起点/祭坛/Boss）与相邻层全连、豁免列差**；边不交叉 |
| 可达性 | `isReachable` = 上一层所选（或单节点）的出边目标；`chooseNode` 拒绝不可达；未记录选择（开发者跳关）按第 0 列兜底 |
| 重掷 | 整图校验不过就重掷，上限 **80 次**；仍不过走**兜底图**（三列菱形 + 定式边，数学上必过全部校验）——「生成必成功」有测试钉死 |
| 类型 | 稀有节点全局布置：**精英 2~4 个落在 l2~l6 的不同层**（l1 与 l7 不受理）、**篝火 1~3 个落在不同中段层**（§3.2.4）；其余节点在本层 `kinds`（去掉 elite/rest）里按 `weights` 抽环境类型 |
| 精英池 | 同幕按层序抽、后排斥前；act1 池 = `rust_warden`（全幕只有这一只，见疑问清单），act2 池 = `sanctum_jailer/tidecaller` |
| 幕隔离 | 幕 id 混进种子（`actSeed`）：同一 `run.seed` 下 act1 / act2 生成**两张不同的图** |

### 2. 决策点密度与走廊（§3.1 修订 2 / §3.4）

生成后逐图校验，任一不过整图重掷：

| 校验 | 阈值 | 实测（400 种子/幕） |
|---|---|---|
| 三分叉（出度 ≥3 的中段节点） | ≥2 | 均值 2.2（2~4） |
| 汇合点（入度 ≥2 的中段节点） | ≥2 | 均值 9.5 |
| start→Boss 可行路径数 | ≥8 | 12~154，均值 ~51 |
| 安全走廊（精英 ≤1 且篝火 ≥1） | 必存 | 400 种子全过 |
| 贪婪走廊（精英 ≥2） | 必存 | 400 种子全过 |

### 3. 存档与工程（§六）

| 项 | 实现 |
|---|---|
| SCHEMA | **12 → 13**。迁移 `12`：带 `run`/`deck` 的**进度档置 null**（回标题页），meta / settings / codex / replay 原样通过 |
| 地图段 | 沿用 `layerIndex + picked`（每层所选列）。地图是 `(act, seed)` 的纯函数，「当前节点 id」由 `currentNodeId` 推导，语义等价 |

### 4. 可见性与 UI（§四）

- `MapView.vue`：**10 层竖排、层内按 `col` 分列**，SVG 蚀刻线做边、当前描金脉冲、可达亮起、已走描边、未达**不置灰**。
- **节点改圆球 + 内联图标（甲方定稿，2026-10-07）**：长方形卡片太臃肿 → 46px 圆球，**不显示节点名**，只用「图标 + 类型标签」：剑=战斗 / 星=精英（紫）/ 火=休息 / 锤=祭坛 / 匣=奖励 / 骷髅=首领（血）/ ？=事件。图标是**手写内联 SVG**（`viewBox 0 0 24 24`，`fill:none; stroke:currentColor`），不依赖任何字体或 emoji——玩家机器上没有对应字体也不会变豆腐块。名字保留在 `:title` 悬停里。
- **地图自下而上（爬塔感，甲方定稿）**：l0 起点在最底、Boss 在最顶；`y = MAP_TOP + (末层 − 层号) × ROW_H`，视口从底部起、随推进向上滚（CDP：入口 scrollTop 208 → 中段 70 → Boss 层 0）。
- **布局改为「每层居中」（甲方定稿，2026-10-07「看起来肿、不平衡」）**：横向坐标不再直接吃 `col`，而是按**层内序号**居中排布（`x = 中轴 + (序号 − (n−1)/2) × COL_W`）——拓扑的列差约束仍由 `col` 决定，但视觉上每层都对称，**脊椎（起点/祭坛/Boss）永远落在一根中轴上**，整张图呈对称菱形。
- **间距再调（甲方：「上下排序很挤」）**：行距是纵向观感的关键，`ROW_H` 从 54 提到 **74**（相邻两行中心距 ≈ 2× 圆球直径），层与层的空隙不再被类型标签塞满；列距同步放宽到 `COL_W 168`，让菱形占住更多横向画面，而不是缩成中间一条窄柱。视口 `flex: 1` 吃满舞台剩余高度（612px），10 层（MAP_H 776px）**超出时纵向滚动 + 当前层自动居中**；标题缩到 20px 并把边距收死，多让出约 20px 给地图。
- **超出视口纵向滚动 + 当前位置自动居中**：`.graph-viewport`（500px）内滚动，`currentY` 变化时把当前层滚到视口中间。CDP 实测：10 层图 scrollHeight 644 / clientHeight 500；走到 l4 时 scrollTop=41，到 Boss 层自动滚到底 144。
- 点击即走；不可达 `:disabled` 点不动。

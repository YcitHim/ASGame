## §一 现状诊断：假分支

| 现状（`act1.json` + `core/map/index.ts`） | 问题 |
|---|---|
| 8 层，每层 width 1~3 个候选，`chooseNode` 只在**本层内**选一个 | 层与层之间**零耦合**：这层选什么不影响下层给什么 |
| 候选按层独立生成 | 没有「路径」这个概念，只有「每层抽一次签」 |
| 玩家看不到全局 | 无法规划，「精英→篝火→Boss」的节奏是撞上的，不是走出来的 |

一句话：现在的地图提供的是「每层的偏好选择」，不是「整幕的路线选择」。玩家的长期决策（我这局要贪还是要稳）没有落点。

## §二 设计目标：真分支的三个支柱

1. **连通性**——选择有后果：选了左边的精英，就放弃了右边的篝火，而且这个放弃是**看得见、追不回的**。
2. **可见性**——规划成为可能：进幕即见全图，从起点到 Boss 的每条路都能提前推演。
3. **不对称性**——分支有性格：左支「两精英一篝火」、右支「三小怪两事件」，路线选择 = 风险偏好声明。

## §三 结构规格（DAG）

### 3.1 骨架参数

| 项 | 规格 |
|---|---|
| 深度 | **8 层不变**（沿用现有层结构，act1/act2 同规格） |
| 每层节点数 | l0（起点）= 1；l7（Boss）= 1；l6（祭坛）= 1；**中间 l1~l5 每层 2~4 个** |
| 全图节点数 | 13~19 个/幕 |
| 列坐标 | 节点在层内占列（0~3），UI 按列排布 |
| 边 | 只连**相邻两层**；两端列差 ≤1；**边不相交**（平面约束，UI 清爽也让「分支」一眼可读） |
| 连通性 | 除起点外每节点 ≥1 入边；除 Boss 外每节点 ≥1 出边（生成后校验，不合格重新掷） |

### 3.2 节点类型分配

- 每层可用类型**沿用现有 `MapLayerSpec.kinds` 与 weights**（不发明新配比），改为在「该层的 2~4 个节点」上分配，约束三条：
  1. 同层**精英 ≤1**、**篝火 ≤1**；
  2. l1 不出精英（开局不堵门）；
  3. l6/l7 维持祭坛 → Boss 的固定收尾（现状如此，保持）。
- 事件节点只显示「？」图标，内容不可见（现状口径保持）——**可见的是类型，不是结果**。
- 精英池抽取逻辑（同幕按层序抽、后排斥前）原样沿用。

### 3.3 生成与复现

- 同种子同图：结构生成走**独立 `map` RNG 流**（docs/38 已有 map 流口径），新增边生成只消耗该流，不污染 combat/curse 流。
- 生成失败（连通性校验不过）就地重掷该层，最多 10 次后整幕重掷——validator 加一条「所有生成种子连通性必过」的常驻检查。
- 过幕（docs/40）：转幕后按 act2 规格生成新图，互不影响。

## §四 可见性与 UI

| 项 | 规格 |
|---|---|
| 全图 | **进幕即全图可见**（StS 模式）。8 层短幕没有藏图的必要——规划本身就是玩法，藏起来等于没收玩法 |
| 状态 | 当前位置（描金）/ 可达节点（亮起可点）/ 已走路径（描边）/ 未达区域（正常显示，不置灰——全图可见的意义就是能提前看） |
| 移动 | 只能点「与当前节点有边相连的下层节点」；点击即走，不二次确认（节点内容页才是决策点） |
| 布局 | 竖排 8 层、列向展开；边用细蚀刻线；act2 走 `--act-*` 青蓝令牌（docs/43 追认 #10） |
| 美术 | 节点图标沿用现有字形（剑/角/火/砧/匣/颅/？），边与选中态是仅有的新增视觉元素 |

## §五 数值影响与门禁（先说丑话）

**树状地图会让通关率上行**：玩家能绕开精英、能规划篝火时机——这是设计意图（选择权本身就是强度），不是事故。但两条纪律：

1. **不预调任何数值补偿**。先让地图自己跑出门禁数据；通关率若涨出 45~65% 健康区间，那时候的补偿对象是**节点配比**（比如精英出现率），不是敌人数值——地图的账地图还。
2. **门禁独立**：单幕+双幕 400 局复跑（同批种子），与线性图基线对比记录波动；sim AI 需要基础的寻路策略（贪心：血量低偏篝火、否则偏精英/事件——**这不是调 AI 强度，是让 AI 像个普通玩家一样认路**，寻路策略作为 sim 配置项声明，不进游戏逻辑）。
3. golden replay：战斗盘 replay 不受地图影响（战斗内部未动）；**run 级回放（若有）与 sim 基线数字作废重录**——这是本次变更的主要工程成本，一次付清。

## §六 存档与工程

| 项 | 规格 |
|---|---|
| 数据 | RunState 地图段改为「节点表（id/层/列/类型）+ 边表 + 当前节点 id」；层结构保留（深度概念不变） |
| SCHEMA | +1。**旧档迁移裁决：进行中的旧 run 直接作废回标题页，meta（图鉴/成就/解锁/教学）全保留**——旧线性档无法无损映射进 DAG，强行映射比作废更伤信任 |
| 触点 | `core/map/index.ts`（生成/选择/可达性）、`MapView.vue`（重写为全图模式）、`systems/save`（迁移）、sim 寻路策略、validator（连通性常驻检查） |
| 不动 | 节点内容结算（战斗/事件/篝火/祭坛全部沿用）、转幕流程（docs/40）、节点类型集合 |

## §七 排期裁定：地图先，九相 Phase 1 顺延

| 序 | 事项 | 理由 |
|---|---|---|
| 1 | **树状地图**（本文） | 结构变更：它改变**每一局**的骨架，之后所有 sim 数值基线都要长在它上面。后做 = 九相 Phase 1 的门禁数字落地即过期 |
| 2 | **九相 Phase 1**（docs/46） | 顺延至地图封版后开工，**直接在新地图基线上跑 400 局门禁**——一次测准，不用测两遍 |
| 3 | Phase 2 机制静默预建 | 不受影响，随时可写（三条锁不变） |
| 4 | docs/47 act2 敌人配置表 | 策划照常交付（v1.1-B 前），不受地图排期影响 |

两个系统**不并行施工**：地图动 run 结构、九相动战斗结算，同时开工会把 sim/golden 的波动搅成一锅无法归因——一次一个变量，这是 0.5 以来的老规矩。

v1.1「沉没圣堂」的最终形态因此明确为：**树状双幕 + 九相（P1+P2）+ act2 敌人/Boss + 音频层**。

## §八 不做的事

1. 不做迷雾/战争迷雾——全图可见是本设计的支柱，不是阉割项。
2. 不做层内回头、不做横向移动——只向前，肉鸽的悔棋不存在。
3. 不新增节点类型（商店等）——本作无金币，现有七类够用。
4. 不做多入口/多结局分岔——起点唯一、Boss 唯一，分岔只在途中。
5. 不在本次调整节点配比与敌人数值——地图的账先记账，超线再还（§五.1）。

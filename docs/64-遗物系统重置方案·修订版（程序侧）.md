## §零 一句话方案

docs/62 把遗物从「一根数值轴」撑开成「六根轴」——方向对，但一半件仍是「条件满足自动发」，玩家只是**看戏**；本修订版的验收标准只有一条：**每一件遗物，每回合至少要给玩家制造一个「因为拿了它才存在」的决策点**。遗物改变的不是数字，是「这一回合你要算的东西」。

## §一 对 docs/62 的诊断（为什么要修）

62 的病根诊断（19/22 件是纯数值排列组合）是准的，六轴模型也对。但方案本身仍有三处没到位：

1. **「自动件」比例还是高**。完好之镜（满血自动抽 1）、回声号角（开局自动全体胆怯）、商人算盘（商店自动打折）——玩家拿到后**没有任何新操作**，体验仍是「数值大一点」的变体，只是包装成了条件。自动件可以有（当教学锚），但不能占编制。
2. **缺「节奏轴」**。本作最独有的决策资源是**出牌排序、手牌打空、空过止损、连打爆发、充能憋泄**——62 只碰了憋泄（熔炉之心）和排序（齿轮币），其余空白。而这些恰恰是「好玩」的主战场：它们让同一副卡组因为一件遗物长出完全不同的回合结构。
3. **引擎方案不可持续**。62 的第三批/第四批是 9 项**逐件**引擎手术（onKill 改一处、双结算改一处、格挡保留改一处……），每件规则遗物都是一次独立的 core 改动。下次再加规则件，又要再开一次刀。

---

## §二 设计原则升级：从「六轴」到「决策点密度」

保留 62 的六轴生态位模型，新增三条硬规矩：

1. **决策点密度 ≥1/回合**：每件遗物写明「它改变了哪条决策曲线」（见 §五 每件末列）。纯自动件全池 ≤4 件，且只能是教学锚或经济锚。
2. **机制成长线**：T1 教的机制，T3 给同主题的规则放大版——玩家在第一局埋下的理解，要在后面的局里兑现（例：空腹铃铛 T1「空手→格挡」→ 唱诗班终曲 T3「空手→过牌」）。
3. **风险要有翻盘面**：62 的风险件只有红王冠（慢性失血）一种形态。风险应该还包括**赌博方差**与**绝地翻盘**——高潮时刻是口碑的来源。

## §三 引擎架构升级（本修订版最重要的一处）

### 3.1 问题

遗物目前**纯数据驱动、没有 handler**（`core/combat/relics.ts` 只按 `timing` 派发 `effects`）。所以 62 里凡是要「改规则」的件（双结算、格挡保留、受击减半、触顶参数化），每一件都要单独改一个结算函数。

### 3.2 方案：`core/registry/relic-handler.ts`（与 trait-handler 同构）

特性系统（docs/58）已验证过的成功模式：**引擎问「能力」而不是查「id」**。照搬：

```ts
interface RelicHandler {
  // —— 新时机（数据件也能用，注册即全池可用）——
  onBattleWin?(params, ctx): void;     // 泛黄照片 / 朝圣者之铃
  onHeal?(params, ctx): void;          // 脏绷带（挂 healUnit 单一汇点，嗜血 healBonus 同点）
  onKill?(params, ctx): void;          // 死亡面具
  onExhaust?(params, ctx): void;       // 燔祭之书
  onRelicGain?(params, ctx): void;     // 寻锈杖
  // —— 规则问询（引擎在结算点统一问一次，不问 id）——
  firstCardDouble?(params): boolean;   // 双重钟摆：每回合第一张牌结算两次
  keepBlock?(params): number;          // 镜面装甲：回合结束保留格挡比例/上限
  cheatDeath?(params, ctx): boolean;   // 第二颗心脏：HP 归零时改为剩 1（每场一次）
  firstAttackScope?(params): number;   // 磨刀石：本场第一张攻击牌加伤
  pollutionOverflow?(params): { backlashMult: number; fallTo: number }; // 泄压阀：触顶参数化
  shopDiscount?(params): number;       // （备选）商人算盘
}
```

- **数值全在 `data/relics/*.json` 的 params**——调数值不改代码（与特性系统同构，docs/58 铁律 6 的同款护栏：禁 id 特判）。
- 一次 engine 投资，**以后新增规则遗物 = 纯 JSON + 注册一行**；62 的 9 项零散手术全部并入本批。
- 同时新增 3 个上下文计数（低成本）：`attacksPlayedThisTurn`（饥锈胃袋）、`prevTurnCardsPlayed`（停摆八音盒）、`triggeredThisBattle` 已有。

### 3.3 成本对照

| | docs/62 | 本修订版 |
|---|---|---|
| 新时机 5 个 | 逐件改 core（中×5） | 批 0 一次做掉（中×1） |
| 规则件 5 件 | 逐件改结算函数（中高×5） | 问询接口 + params（中×1 + 零×5） |
| 下一件规则遗物 | 再开一次刀 | 纯 JSON |

## §六 池子与获取结构（沿用 62 §六，两处同步）

1. T1 ≥6 约束满足（10 件），validator 不动。
2. 当铺池（T1+T2）= 22 件，不变。
3. 解锁位：`engineer_first_clear` → **双重钟摆**（同 62 §六.3）；`three_classes_clear` → 朝圣者之铃。回声号角移除后无解锁位牵连（它本非解锁件）。
4. 其余获取规则（同种子同结果 / 不可重复 / 锈蚀二选一）不动。
5. **老存档兼容**：翻新件沿用 id，老存档已持有者效果静默变更（甲方已在 62 层面默认接受，本版沿用）；被移除的回声号角在老存档中若已持有 → 加载时按「未知遗物」剔除并记录（走炉心余烬同款下架流程）。

### 11.2 顺手修掉的 3 个真 bug（甲方「顺便检查一下 bug」）

1. **齿轮币从来没触发过（现版实锤）**：`resolveTriggers` 的 once:turn/battle 是「派发即消耗」——齿轮币（第 3 张牌才生效的条件）在每回合第 1 张牌就把「每回合一次」白白消耗，**自 1.0 上线起从未抽过一张牌**。修复：条件全不满足不消耗 once（`mayProduceEffect` 预评估，延迟效果/异常保守放行）。卡牌 power 同一 bug 同点修复。回归：p28「齿轮币：每回合第 3 张牌 +1 能量」。
2. **隔热砖上线即死循环（拦在发布前）**：onBlock 触发 → +1 格挡 → 再次 onBlock → 无限递归（测试 worker 直接 OOM 崩掉，exit 134）。修复：效果动作携带 `triggerTiming`，onBlock 只在「来源不是 onBlock 自己」时派发——第三捧灰/空腹铃铛给的格挡照样触发隔热砖（化学保留），隔热砖自己的 +1 不再自循环（飞升齿轮 `suppressTriggers` 同款护栏）。回归：p28「隔热砖……护栏钉死」。
3. **回合开始时序让脏绷带白给**：原顺序「再生回血 → 清格挡」，绷带「回血 +2 格挡」在同一回合开始被立即清掉。改为**先清格挡、再回血**（该窗口无任何结算读 player.block，现版零观测差异，golden 12 盘零漂移佐证）。回归：p28「脏绷带：再生回血也能活过格挡清理」。

## §一 结论先行

**寻锈杖的负收益定性为「模拟器侧偏差」，建议按 docs/43 §2.2 销案——不移出池、不改数值。**

理由分三层，逐层给出证据：

1. **效果本身在引擎里是单调增益**：`draw 2`（`src/core/combat/resolve.ts` 的 `drawCards`）没有任何手牌上限截断，开局多两张牌是**严格的超集**——不可能让一个理性出牌者更差。
2. **负差在换种子后仍可复现，但幅度在 1.5~6.0pp 之间大幅波动**，且**在局内三个计数维度上全部解释不了**（承伤反而更低、回合反而更少）。
3. **唯一的物理通道是"下游随机流偏移"**：多抽两张会改变抽牌堆顺序、并在后续洗牌时多/少消耗一次 combat RNG 流，所以两臂从第 1 回合之后就不是"同种子同牌序"了。用同一批种子做件间对比的前提，在这件遗物上**不成立**。

## §二 证据 A：换种子批重复性验证

单幕 normal·锈语者·`simulateRun(..., companionId = "" vs "rust_dowsing")`。三批种子**互不相交**：

| 种子批（各 400 局） | 空随身槽 | 寻锈杖 | 差值 |
|---|---|---|---|
| 1..400 | 35.8% | 30.5% | **−5.3pp** |
| 1001..1400 | 37.0% | 31.0% | **−6.0pp** |
| 2001..2400 | 33.5% | 32.0% | **−1.5pp** |
| 合计 1200 局 | ≈35.4% | ≈31.2% | **−4.2pp** |

**读法**：符号稳定为负（不是单批噪声），但绝对值在 −1.5 ~ −6.0pp 之间跳动近 4 倍。若这是一个真实的机制性负收益，三批的幅度应该收敛；现在这种跳法，更像"每次开局都给玩家换了一副牌序"的运气分布。

复现：`npx tsx tools/headless-sim/src/probe-rust-dowsing.ts`

## §三 证据 B：逐战斗对账

### 3.1 局内计数（同批 400 局，1..400 批）

| 锈语者 | 通关率 | 平均承伤 | 平均回合 | 平均战斗数 |
|---|---|---|---|---|
| 空随身槽 | 35.8% | 53.1 | 26.5 | 4.1 |
| 寻锈杖 | 30.5% | **52.3** | **25.8** | 4.1 |

- 平均战斗数**完全一致**（4.1）——不是"多打了一场"或"少打了一场"。
- 承伤与回合**更低**，但通关率更差。这两个计数被"败局更早结束"污染了：输得多 → 平均回合被死人拉低 → 平均承伤同步下降。**它们解释不了负收益，反而再次说明负收益发生在战斗内部。**
- 污染峰值上一轮已测（80.9 vs 79.8，差 +1.1，两臂都贴着 80 门槛），同样无解释力。

### 3.2 机制对账（读 core）

```ts
// src/core/combat/resolve.ts · drawCards
for (let i = 0; i < count; i += 1) {
  if (draft.draw.length === 0) {
    if (draft.discard.length === 0) break;
    draft.draw = draft.rng.stream("combat").shuffle(draft.discard);  // ← 洗牌消耗 RNG 流
    ...
  }
  const card = draft.draw.shift();
  draft.hand.push(card);   // ← 无 handSize 截断
}
```

- **没有手牌上限**：`drawCards` 只往 `draft.hand` 里 push，`handSize` 只在"回合开始补牌到 5 张"时用到（`reducer.ts:136`）。开局抽 2 张 → 起手 7 张，全部留到第一回合，是纯增量。
- **下游随机流会偏移**：多抽两张会让 `draft.draw` 的剩余序列整体前移 2，并且后续弃牌堆洗入的**时机**也会变（早/晚一次），于是 `rng.stream("combat")` 的消耗序列不再是同一副牌。**"同种子"只保证了洗牌起点相同，保证不了两臂之后的牌序相同。**

## §四 反证：为什么这不能证明"这张牌是弱的"

如果「战斗开始抽 2 张」真的会让锈语者更弱，那么它必须在某个环节**抵消掉两张白送的牌**。可能的抵消机制只有三类，逐一排除：

| 假设 | 检验 | 结果 |
|---|---|---|
| 多抽牌导致手牌溢出、被丢弃 | 读 `drawCards`：无上限截断 | ❌ 不成立 |
| 多出牌加速污染，更早吃反噬 | 污染峰值 80.9 vs 79.8 | ❌ 差 1.1，无解释力 |
| 多抽牌挤掉后续回合的关键牌 | 抽牌堆只是"整体前移"，不是"少牌" | ❌ 总量不变，无系统性损失 |
| AI 手牌越多、选牌越差 | 无法从 sim 外部证伪 | ⚠️ **唯一无法排除的一条** |

最后一条是可查的、也是我唯一不放心的地方：**确定性 AI 的启发式打分可能对"手牌规模"敏感**（例如固定只评估前 N 张、或平局时按索引选牌）。这次的负差符号稳定、幅度不稳，最像这类"策略噪声 + RNG 偏移"的叠加，而不是牌的强度问题。

---

## §五 建议

1. **本件销案**（不移出池、不改数值、不改触发）。它满足 docs/43 §2.2 的销案条件：「若最终定性为模拟器侧偏差，该件直接销案」。
2. **把"AI 对大手牌的选择质量"记入模拟器待改进项**（不阻塞 1.0.x）：等 sim 的选牌策略升级后，重跑 `sim:companions` 复核一次；若那时仍稳定负收益，再回来讨论触发。
3. **不建议按数据改牌**：在没有机制解释的前提下改 `draw 2`（改成 `draw 1`、改成"首回合抽 2"），很可能是在修 AI 的毛病，把一张设计上干净的通用件改成四不像——这正是 docs/43 §2.2 要求"先查明成因而非先动刀"的本意。

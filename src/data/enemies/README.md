# enemies/ · 敌人数据（属性 + 意图表）

## 单敌 JSON 要点
- 属性：HP 区间（combat RNG 取）、格挡、抗性
- 意图表：权重 + 条件分支 + 连续限制；类型见 `core/intents/README.md`
- 预留：多段行动 / summon / 阶段转换（P2 换表）字段

## 蓄力设计规范（docs/18 冻结，务必遵守）

1. **小怪 / 精英走「蓄力链叠加」，Boss 走「阶段递增」**。
   - 链长按敌型：**法术型蓄 2**（蓄 → 蓄 → 释放，如布道者、看守）；**物理型蓄 1**（蓄 → 释放，如重装兵、哨兵）。**不写无限链**（校验上限 3 环）。
   - Boss（锈喉）不叠加：releaseOverride 写死释放值，走 HP 分阶段递增（16 → 24）。
2. **释放值 = 普攻基准 + 蓄力值 × 层数**。thenIntent 末端的攻击只写**普攻基准**，charge 的 value 是**每层一次性增幅值**；只有 Boss 用 releaseOverride 例外写死。层数释放即消耗，**禁止用永久力量实现递增**（0.1 曾滚雪球 26→38）。
3. **蓄力回合要架格挡**（charge 的 block 字段），否则蓄 2 回合 = 白送玩家两轮输出，威胁退化成喘息。
4. 一切蓄力必须声明 thenIntent 且链尾必须是攻击 —— **内容校验器强制**，违规 npm run validate 直接失败。

数据写法（法术型蓄 2，释放 7 + 2×2 = 11）：

~~~json
{
  "intent": {
    "kind": "charge",
    "value": 2,
    "block": 4,
    "thenIntent": {
      "kind": "charge",
      "value": 2,
      "block": 4,
      "thenIntent": { "kind": "attack", "value": 7 }
    }
  },
  "weight": 1
}
~~~

Boss 例外（写死 16）：

~~~json
{
  "intent": {
    "kind": "charge",
    "value": 3,
    "releaseOverride": 16,
    "thenIntent": { "kind": "attack", "value": 16 }
  },
  "weight": 2
}
~~~

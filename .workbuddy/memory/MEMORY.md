# 《锈与血》项目长期约定

## 角色与协作模式
- 用户扮演「玩家 + 甲方」，助手在项目里分饰「策划」与「程序」两侧的参谋；程序侧产出疑问清单，策划侧负责拍板。
- 文档编号协作：docs/ 下按序号滚动（09 任务分解 / 11 技术债 / 12 策划确认 / 13 启动清单 / 14 疑问清单 / 15 执行单 / 16 阶段指示 / 17 疑问 / 18 解答 …）。

## 协作规则（用户明确要求）
- **程序疑问清单的解答必须单独成档**：不能只回填问题清单，要生成独立解答文档（自包含、程序看一份即可开工），并在原问题清单头部加指向链接。先例：docs/15（对应 docs/14）、docs/18（对应 docs/17）。

## 设计铁律（策划已冻结）
- 蓄力必须声明 thenIntent；禁新增永久力量，增幅优先限时/一次性（docs/14 Q12）。
- 蓄力链：小怪/精英走链式叠加（法术型蓄 2/物理型蓄 1，释放=普攻基准+蓄力值×层数，释放清零）；Boss 写死走阶段递增（docs/18）。
- 减益参数 = 剩余回合数；强化只作用于机制卡且只走修饰管线。
- 难度判定以真人实测为准，模拟器只作兜底（0.1「无脑攻击」教训）。
- 数值改动验收：sim 复跑（30%~70% 健康，期望 45%~60%）+ golden replay 随改随录。
